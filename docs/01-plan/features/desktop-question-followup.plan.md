# desktop-question-followup — Plan

2026-10-02 · bkit PDCA / plan-plus · phase 44

## 1. 사용자 의도와 성공 기준
사용자가 다음 개발로 ‘데스크톱 질문 이력·이어 묻기 — 이전 질문과 답을 다시 열고 후속 질문하기’를 선택했다. 범위·결정의 원천은 [PRD §3-8 DC-13·§8](../../PRD.md), [ADR-083](../../ADR.md)이며 이 문서는 이를 확장하지 않는다.

## 2. 전제·대안·YAGNI
기존 이력/답/질문 API, 부모 질문 SQL, 암호화 대기열이 있다. 수동 조회 유지안은 후속 질문을 해결하지 못하며 별도 대화 저장소안은 범위를 넘는다. 기존 IPC를 연결하고 화면 생명주기를 보완하는 안을 따른다. 새 provider·DB·이력 검색/삭제·대화 트리·영구 캐시는 제외한다.

## 3. 요구사항과 범위
DC-13: 자동 이력 조회, 한국어 상태/빈 상태/오류 재시도/더 보기, 현재 답 재조회, 부모를 표시하는 명시적 이어 묻기, 초안을 유지하는 새 질문 전환, 실패 보존·중복 전송 방지·늦은 콜백 폐기. 설치된 0.1.1과 phase 43 메일 게이트는 별도다.

## 4. 성공 조건
SC1 이력 진입/페이지 이동/오류·빈 상태가 작동한다. SC2 현재 답 재열람과 이어 묻기가 실제 IPC에서 부모 ID를 전달한다. SC3 새 질문은 null 부모이며 실패 시 초안/부모 보존·중복 발송 없음. SC4 탭 이탈/로그아웃의 늦은 응답이 노출되지 않는다. SC5 오프라인 후속 질문은 기존 대기열에서 부모를 보존하며 403은 보관되지 않는다. SC6 desktop/root 검증·독립 gap 분석·실행 기록이 있다.

## 5. 위험·아키텍처·규칙
권한 회수는 SQL/답 조회가 집행하며 UI에 복제하지 않는다. 자동 조회의 늦은 응답·중복 클릭은 컴포넌트 요청 세대와 잠금으로 막는다. 흐름: 이력→답 재검사→명시적 부모→기존 IPC/대기열→기존 SQL→폴링. 기존 컴포넌트/IPC 경계를 유지한다. 테스트는 합성 Electron+회귀 단위/SQL로 분리하고 실제 메일·운영 검증과 혼동하지 않는다.

## 6. 진행 순서·기록
상위 문서→design→phase 44 step→실패하는 UI 시나리오→구현→검증→analyze/필요한 iterate→report. Graft 전후 시도와 Archify 실행 결과를 검증 문서에 연결한다. 사용자 선택 외의 질문을 추가할 필요가 없는 기존 기능 확장이다. 도메인/SMTP는 사용자 지시에 따라 보류한다.
