# 웹 회의 녹음 — 계획 어댑터

- 날짜: 2026-09-17 · 방식: Plan Plus · 상태: 설계 작성 완료(2026-09-17) → 구현·로컬 검증(phase 23, 2026-09-29 d52c002) → step4-B1 전사 메타데이터 계약 로컬 검증, 실제 기기·운영 게이트 미완료. 설계 어댑터: [browser-meeting-recording.design.md](../../02-design/features/browser-meeting-recording.design.md)
- 이 파일에는 독립적인 요구 결정을 두지 않는다. 범위 원천은 [PRD §3-4·§8](../../PRD.md)이며 상세는 [웹 회의 녹음 설계](../../planning/웹회의_녹음_설계.md)다.

## Executive Summary

| 관점 | 상위 문서 요약 |
|---|---|
| 문제 | 대면·온라인 회의 내용을 별도 파일 작업 없이 기록할 필요 |
| 해결 | 웹 직접 녹음 우선, Meet·Zoom 공식 자료 수집은 다음 단계 |
| 기능/UX | 입력 테스트 → 녹음 → 재생·복구 → 전사 검토·확정 |
| 핵심 가치 | 회의 기록을 검증 가능한 업무 근거로 연결 |

## 요구·대안·검증 매핑

| 항목 | 원천 |
|---|---|
| 사용자 의도·대상·완료 기준 | PRD §3-4, 상세 설계 §1·§10 |

| 구조·데이터·실패 처리 | ARCHITECTURE의 ADR-056 절, 상세 설계 §4~§6 |
| 개발 영향·실행 명세 | 상세 설계 §9, phases/23-browser-meeting-recording |

## 합의 기록

- 사용자가 대면 직접 녹음과 Meet·Zoom 회의 기록 설계를 요청했다.
- 온라인 회의는 주최자/공동 주최자 계정뿐 아니라 개인 PC 소리 녹음도 허용했다.
- 웹 직접 녹음 먼저, 공식 계정 연동 다음, PC 앱·봇 후속이라는 추천 순서를 선택하고 설계를 요청했다.
- 기존 30분 전사·동의·RLS·공유 데모 무쓰기 경계에 맞춘 구체 계약은 상위 PRD/ADR과 상세 설계에 기록했다. 이 합의는 구현·운영 반영 완료를 뜻하지 않는다.
