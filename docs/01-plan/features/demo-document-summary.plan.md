# demo-document-summary — Plan

2026-10-07 · bkit PDCA · phase 53 · 원천 PRD §6-7 "데모 문서 요약"·§8 "데모 문서 요약 범위", ADR-092.

## Executive Summary

| 관점 | 내용 |
|---|---|
| Problem | 데모 「문서」 화면이 자료 목록과 고정 문장만 보여 줘, 체크리스트가 소개하는 문서 요약(한눈에 보기·결정·할 일·질문·원문 근거)을 데모에서 볼 수 없다. |
| Solution | 데모 부서 문서 요약만 익명으로 읽는 정책을 더하고, 읽을 때 원문으로 다시 검증한 요약을 실제 화면과 같은 구역으로 렌더한다. 시드에 결정·할 일·질문이 담긴 합성 문서를 더한다. |
| Function/UX Effect | 심사위원·방문자가 로그인 없이 문서 요약과 원문 근거를 확인한다. 한눈에 보기는 원문 문장만 보인다(phase 51 규칙). |
| Core Value | 데모가 실제 제품과 같은 화면·같은 검증을 보여 준다. |

## Context Anchor

| Key | Value |
|---|---|
| WHY | 데모의 "문서 정리" 소개와 실제 데모 화면 불일치, phase 51 결과가 데모에 안 보임 |
| WHO | 로그인 없는 데모 방문자(심사위원·잠재 고객) |
| RISK | 익명 읽기 범위가 데모 밖으로 새는 것 · 재시드가 다른 데모 화면을 바꾸는 것 |
| SUCCESS | SC1 SQL: 익명은 데모 요약만 읽고 쓰기 불가 · SC2 단위: 읽기 시 재검증(원문에 없는 문장 비렌더) · SC3 E2E: 데모 문서 화면에 요약 구역과 원문 문장 overview · SC4 lint·test·build·기존 데모 E2E 회귀 |
| SCOPE | PRD §6-7·§8 / ADR-092 |

## 2. Scope

- 포함: migration 1개(anon SELECT 정책), 문서 요약 검증 순수 모듈 분리, 데모 데이터 로더·데모 문서 화면, 실제 문서 화면 요약 구역의 공유 컴포넌트화, 시드(지원서 overview 원문화 + 합성 문서 1건), 테스트(SQL·단위·E2E).
- 제외: 데모 업로드·정리 시작, 쓰기 정책·RPC·새 테이블, 실제 문서 화면 동작 변경, 데모 외 화면 라벨 변경("근거 N개" 표기 등은 별도).

## 3. Requirements

| ID | 요구 | 우선 |
|---|---|---|
| FR1 | `document_summaries_demo_read`: `to anon` SELECT, `is_demo_department(dept_id)` 이고 같은 부서의 활성 소스 | 높음 |
| FR2 | 데모 로더가 부서의 문서 요약을 읽고, 소스별 원문 items로 `verifyDocumentSummary`를 적용해 유효 인용이 1개 이상인 요약만 반환 | 높음 |
| FR3 | 데모 문서 화면: 요약이 있는 자료는 실제 화면과 같은 구역(한눈에 보기·핵심 내용·결정·정책·다음 할 일·확인이 필요한 질문·원문 근거 N)을 표시, 없으면 기존 표시 유지 | 높음 |
| FR4 | 요약 구역 렌더를 공유 컴포넌트로 빼서 실제 「문서」 화면과 데모가 같은 라벨·순서를 쓴다(실제 화면 출력 불변) | 중간 |
| FR5 | 검증 함수(`groundedOverview`·`verifyDocumentSummary`)를 LLM·DB import가 없는 모듈로 분리, 파이프라인은 그 모듈을 사용(동작 불변) | 중간 |
| FR6 | 시드: 지원서 3건 overview를 원문 문장(검증 항목 앞 2개)으로, 개발 부서에 합성 문서 1건(핵심 내용·결정·정책·다음 할 일·확인이 필요한 질문) 추가 | 높음 |

## 4. Success Criteria

SC1 SQL 하니스: anon 데모 요약 SELECT 1행, 비데모 0행, INSERT/UPDATE/DELETE 거부. SC2 단위: 원문에 없는 overview·항목·인용이 데모 로더 결과에서 빠짐, 시드 요약 `dropped === 0`. SC3 E2E(로컬 QA·운영 반영 후 운영): 합성 문서 펼침 시 요약 구역 표시, overview 문장 모두 원문 기록에 존재. SC4 lint·test·build·기존 데모 E2E 통과.

## 5. Risks

| 위험 | 완화 |
|---|---|
| 익명 읽기가 데모 밖으로 확장 | `is_demo_department` + 같은 부서 활성 소스 조건, SQL 하니스 음성 검사 |
| 재시드가 다른 데모 화면을 바꿈 | 시드는 데모 조직만 truncate·재생성(LLM 호출 없음), 기존 데모 E2E 회귀 |
| 배포 순서 | 읽기 시 재검증으로 순서 무관하게 원문 없는 문장 비렌더. 순서는 migration → 재시드 → 병합 |
