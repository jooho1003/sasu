# desktop-recent-work — Plan

## Executive Summary

| 관점 | 내용 |
|---|---|
| 문제 | 작업 시작 화면을 떠나면 앱에서 맡긴 작업을 다시 찾기 어렵다. |
| 해결 | 기존 받은 일의 최근 자료·영업 상태를 일 맡기기에 표시하고 현재 권한으로 다시 연다. |
| 사용 효과 | 한국어 상태·새로고침·오류 재시도와 웹 상세 연결을 제공한다. |
| 핵심 가치 | 현재 권한과 암호화/세션 경계를 유지하며 기존 작업을 재실행하지 않는다. |

## Context Anchor

WHY 작업 재열람 / WHO 동의한 팀장 / RISK 늦은 응답·권한 회수·실패를 빈 상태로 오인 / SUCCESS SC1~5 / SCOPE PRD DC-14·§8, ADR-084.

## 1. 개요

원천: [PRD DC-14·§8](../../PRD.md), [ARCHITECTURE §6-12](../../ARCHITECTURE.md), [ADR-084](../../ADR.md). 사용자의 다음 개발 요청에 따라 기존 DC-08·09의 재열람 공백을 우선 보완한다. 새 사업 요구나 외부 서비스 선택은 없다.

## 2. 범위

포함: 최근 24시간 본인 자료/영업 요약, 기존 새로고침 공유, 현재 권한 확인·웹 인계·성공 후 읽음, 실패/이탈/연타 처리.
제외: 전체 이력, 검색, 새 API/DB/LLM, 자동 재실행, SMTP/새 설치 파일 게시.

## 3. 요구사항

DC-14와 설계 U1~6/S1~2로 비교한다. 팀원 요청 권한은 서버가 집행하며 UI는 팀장 흐름만 표시한다. 목록은 메모리로만 유지한다.

## 4. 성공 조건

SC1 팀장 최근 작업과 모든 한국어 상태/빈 상태 표시. SC2 로딩/오류 구분·재시도/공유 갱신. SC3 현재 권한 확인 후 웹 인계·읽음, 연타 1회. SC4 실패·권한 회수·탭 이탈/로그아웃 늦은 응답 미인계/미읽음. SC5 Electron 회귀·단위/lint/build·독립 분석/기록.

## 5. 위험

받은 일 실패 시 이전 작업을 최신으로 보이지 않게 숨긴다. 권한 확인 뒤에도 웹이 현재 세션/RLS를 집행한다. 요청 중복은 App 공유 promise와 RecentWork ref 잠금으로 방지한다.

## 6. 영향 분석

변경: App 받은 일/읽음 lifecycle, WorkTab props, 신규 RecentWork renderer. 영향 소비자: CardsTab(inbox), 펫/알림(main 기존 E05), 작업 시작/질문·로그아웃 UI. API/공유 contracts/main은 그대로이며 회귀한다.

## 7. 구조·대안

A WorkTab에 모든 로직 삽입(빠르지만 시작 UI와 결합), B 새 이력 서비스/API(범위 과다), C 전용 RecentWork+App 요청 공유(선택). 기존 React/IPC/SQL 경계를 따른다.

## 8. 규칙

한국어·현재 세션·기존 출처 제한·원문 비저장. 신규 lib 모듈 없음. 합성 Electron 증거와 실제 SQL 실행을 분리한다. Graft/Archify 결과와 공백을 기록한다.

design → phase45 step → 테스트/구현 → analyze/필요한 iterate → report. 개발 브랜치는 PR30을 전제로 하며 운영 게시와 구분한다.
