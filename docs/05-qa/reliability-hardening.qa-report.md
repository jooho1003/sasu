# 후속 안정성 개발·평가 기록

날짜: 2026-09-12. 상태: **일부 안정성 개발 완료, 전체 개발/실환경 검증 미완료**. 아래 실행 결과를 확인하면서 다음 수정까지 연속 진행했다. 운영 DB 적용·배포·공모전 최종 제출을 완료한 보고가 아니다.

## 구현 순서와 검증

1. **공통 워커 진입점:** `lib/worker.ts`에서 9개 파이프라인을 등록하고 pending sweep 후 claim한다. 정기 HTTP와 after 콜백을 통합했다. 경로별 unknown_kind 실패 및 sweep job 미생성으로 정리가 실행되지 않는 문제를 보완했다.
2. **답변 인용 전체 검증:** 일부 인용만 맞는 초안을 그대로 게시하지 않는다. 1회 재생성 후에도 인용 검증 실패면 canonical refused만 저장·게시한다. 완료 RPC의 늦은 결과 차단은 유지한다.
3. **Slack 원자 수신:** `0014_atomic_slack_ingest.sql`에서 이벤트 키·item 또는 answer·job을 한 트랜잭션으로 저장한다. 소스 활성/동의를 DB 안에서 잠금 후 재검증하고 데모 조직은 제외한다. 미동의 본문은 저장하지 않는다. 일반 재전달로 삭제된 원본을 복원하지 않는다.
4. **실제 모델 거절 처리:** 게이트웨이가 반환하는 llm_refusal을 Q&A의 refused로 종료한다. 네트워크/DB 실패는 근거 부족으로 숨기지 않는다.
5. **작업 완료 기록 실패 분리:** handler 성공 후 jobs 완료 기록이 실패하면 handler 실패로 오인해 재큐잉하지 않는다. running 상태의 수동/lease 복구는 남은 작업이다.
6. **원문/분류 쓰기 경계:** 일반 사용자의 items·citations UPDATE/DELETE와 classifications INSERT/UPDATE/DELETE 권한을 0015에서 회수했다. 수집/워커 service role, SELECT RLS, 문서/회의 업로드 INSERT는 유지했다. 허용되는 신규 입력을 통한 위조 방지까지 전부 해결했다는 뜻은 아니다.

## 실제 답변 평가

`npx vitest run --config vitest.eval.config.ts tests/evals/answer-live.eval.ts`

모델 `openai/gpt-oss-120b`, 6회 호출, 입력 2,790/출력 3,391토큰. 네 가지 단순 사실 질문, 관련 없는 근거의 질문, 근거가 없는 질문으로 구성했다. [ID별 원시 결과](../verification/evaluation-results/answer-live.json).

이는 독립 검수되지 않은 작은 합성 스모크 평가다. 자동 판정은 예상 사실 문자열·인용 문자열·refused 상태에 한정된다. 복잡한 추론 정확도나 모든 문장의 의미적 뒷받침을 보장하지 않는다. llm_calls 기록만 기존 게이트웨이로 시도했으며 실제 업무 저장·Slack 발송은 모의 처리했다. 이전 분류 62/64 결과를 다시 실행하거나 개선됐다고 덮어쓰지 않았다.

## 실제 E2E 실패와 실행 제한

로컬 프로덕션 서버 3101에서 전체 `npm run e2e`를 실행했다. 게스트 네 검사는 통과했고, 기존 세로 슬라이스는 seed 계정 로그인 후 최초 Slack 이벤트 POST에서 500으로 실패했다. 이후 워커/카드/결정/발송 단계에 도달하지 않았다. 연결 DB의 신규 RPC를 무효 인수로 확인한 결과 HTTP 404 / PGRST202였다. 마이그레이션이 로컬에만 존재하므로 앱부터 배포하면 안 된다.

이 테스트는 성공 시 실제 DB 쓰기와 Slack 발송을 포함한다. 반복 실행 전 명시적 환경 승인을 요구하도록 `E2E_ALLOW_EXTERNAL_WRITES=1` 게이트를 추가했다. 이것은 위 실패를 통과로 바꾼 것이 아니다. 기본 스킵과 실제 통과는 구분한다. 이번 QA 서버는 검증 후 종료했다.

## 승인 후 후속 실행

2026-09-12 사용자 발송 승인 후 연결 DB에 0012~0015 적용 및 실제 DM 발송·결정·원장 E2E가 통과했다. 위 실패 기록은 적용 전 이력이며, 최신 결과와 검증 한계는 [실제 발송 보고서](live-delivery.qa-report.md)를 따른다. 배포는 Vercel 로그인 필요 상태다.

## 다음 단계와 아직 남은 개발

- **실환경 검증:** 연결 DB 0012~0015 적용 및 로컬 앱의 실제 DM 포함 합성 세로 슬라이스 완료. Vercel 로그인 후 앱 배포와 배포 URL에서의 검증이 필요하다.
- **워커 복구:** running lease·소유 토큰·늦은 완료 차단, 외부 전송 결과 불명확 시 중복 없이 처리하는 정책. 완료 기록 실패를 분리한 것만으로 프로세스 종료 복구가 완성되지는 않는다.
- **잔여 권한:** 직접 기록 결정의 비공개 인용 가시성, 신규 items/citations 및 카드 직접 쓰기 정책 분리. 기존 [위험 보고서](../verification/quality-design-review.md)의 미해결 항목 중 위에서 해결한 명령 외의 항목을 유지한다.
- **카드/문서:** 일부 인용 실패 시 자유 서술의 뒷받침, 카드·인용·상태 원자 저장, 문서 재처리의 시작 시각/늦은 완료 보호. 이번 답변 수정이 다른 산출물까지 해결한 것은 아니다.
- **제출 완주:** 온라인 회의 봇의 실제 계정 테스트/컷 판정, 신청 양식 7항목·이미지·스크린샷·서비스 링크 유지·최종 제출 여부 확인. Lindy 계정이 없어 직접 비교 미실행.

## 스킬/도구 상태

QA 스킬의 config-audit는 bkit.config.json 누락 1 CRITICAL, 나머지 네 검사 지적 0. 사용자의 기존 계속 진행 승인을 적용했다. Next.js 스킬의 연결된 부속 문서는 설치 경로에 없어 실행 코드/타입 검사로 보완했다. 이 제약을 검사 전체 PASS로 표시하지 않는다.
