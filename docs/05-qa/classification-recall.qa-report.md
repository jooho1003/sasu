# 분류 누락 개선 QA 보고서

날짜: 2026-09-12. 판정: 회귀 테스트 통과, 실제 모델 평가 2건 불일치 잔존. 운영 배포 및 Lindy 직접 비교는 미실행.

## 변경과 TDD 기록

규칙 비후보를 action/info/chatter로 확정하고 종료하던 분기를 제거했다. 규칙은 보조 신호·마감 추출에 유지하고 모든 유효 저장 항목을 기존 `llm.structured("classify")`로 의미 분류한다. 본문 명령을 따르지 않는 경계와 라벨 정의를 명시했다. 동의·마스킹은 기존 수집 계약, 삭제 항목 제외·4,000자 제한·실패 시 unclassified·자동 승격 기준은 유지한다. 빈 본문은 호출하지 않는다.

- 구현 전 확장 테스트: 22건 중 9건 실패, 13건 통과.
- 구현 후 분류 테스트: 22건 모두 통과.
- 전체 `npm test`: 26파일, 430건 모두 통과.
- `npm run lint`, `npm run build`, `git diff --check`: 모두 종료 코드 0. 빌드는 TypeScript와 페이지 생성까지 완료했다.
- low confidence, 비후보+confidence=null, 비decision, 모델 오류 시 카드 자동 생성 금지 검증 포함.

## 실제 모델 전후 비교

동일 합성 문장 64개, 동일 잠정 정답, 동일 `openai/gpt-oss-20b`로 각 1회 실행했다. 라우팅 정책과 프롬프트가 함께 변경됐으므로 개선분을 둘 중 하나의 효과로만 해석하지 않는다. API 부하와 시점도 달라 지연 차이는 통제된 성능 벤치마크가 아니다.

| 지표 | 변경 전 | 변경 후 |
|---|---|---|
| 정답 | 41/64 (64.1%) | 62/64 (96.9%) |
| 결정 재현율 | 9/16 (56.3%) | 15/16 (93.8%) |
| 결정 정밀도 | 9/9 (100%) | 15/15 (100%) |
| 불일치 | 23건 | 2건 |
| 실제 LLM 호출 | 16회 | 64회 |
| 입력 토큰 | 5,505 | 34,332 |
| 출력 토큰 | 6,190 | 15,608 |
| 항목 처리 시간 합계 | 13,277ms | 37,232ms |

기존 오답 21개 수정, 기존 정답의 회귀 0개. 후보 규칙의 결정 재현율은 여전히 62.5%지만 더는 모델 호출을 차단하지 않는다. 64문장 모두를 검토했으며 결정 하나는 의미 판단 단계에서 여전히 놓쳤다.

금액을 계산하지 않았으므로 호출 4배를 비용 4배라고 표현하지 않는다. 입력 토큰은 약 6.24배, 출력은 약 2.52배다. 전수 호출에 따른 비용·워커 처리량을 실제 운영 부하에서 추가 확인해야 한다.

## 남은 불일치

- C032 “모두 맛점하세요.”: 잠정 정답 chatter, 모델 action. 업무 요청과 관용적 인사의 구분 실패.
- C039 “이 라이브러리 도입 여부를 검토 부탁드립니다.”: 잠정 정답 decision, 모델 action. 미결 도입 판단과 검토 작업 요청의 경계가 모호하다. 실제 팀의 운영 기준과 독립 라벨 검수가 필요하다.

평가 종료 코드는 1이다. 정답을 결과에 맞춰 바꾸거나 남은 두 예문을 프롬프트에 직접 주입하지 않았다. 변경 전 실패 사례를 본 뒤 개선했으므로 `holdout`이라는 기존 분할 이름도 블라인드 인증을 의미하지 않는다. 독립 검수 전까지 이 수치를 실사용 정확도나 Lindy 대비 우월성으로 발표하지 않는다.

## 검증 범위

- L1: 단위·회귀 430개 통과.
- 모델 통합: 실제 Groq 호출, 업무 DB·enqueue 모의 처리. 실제 카드 생성/Slack 발송 없음. 기존 게이트웨이의 llm_calls 저장은 시도하되 성공 여부는 검증하지 않음.
- L2 HTTP·L3 브라우저·L4 사용자 흐름·L5 전체 데이터 흐름: 이번 분류 변경에 대해 미실행. 단위/모델 결과로 이를 통과했다고 판단하지 않음.
- 운영 DB 적용/배포: 미실행. 기존 보안 마이그레이션과 워커 복구의 남은 위험은 별개.

## Pre-Release Scan

QA 스킬의 Windows Bash 경로 오류 후 같은 모듈을 Windows 절대 경로로 실행했다. config-audit의 `bkit.config.json` 누락 1 CRITICAL, 나머지 네 검사 지적 0. 사용자의 명시적 계속 진행 승인에 따라 도구 설정 경고로 기록하고 테스트했다. 검사 전체 PASS라고 표기하지 않는다.

## 제출 기준 정정

제출 필수 문서는 Lindy 기능 격차표가 아니라 원티드 신청·접수 문서다. 저장소 `docs/submission/원티드 지원서.md`의 7항목과 유의사항은 기존 `docs/submission-checklist.md`를 통해 추적한다. 이 파일에서 확인한 것은 양식이며 실제 접수·최종 제출 완료 증거는 아니다. Lindy 비교 계정이 없어 직접 비교는 미실행이다.
