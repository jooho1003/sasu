# Lindy 확장·비교 검증 계획

작성일: 2026-09-12. 상태: 사용자 확인 완료, 분류 누락 개선 및 사수 전후 평가 진행. 이 계획은 확장 전체가 완료됐다는 보고가 아니다.

## 요구사항 변경

사용자가 말한 문서는 **원티드 AI 공모전 신청·접수 문서**로 확인됐다. 저장소의 `docs/submission/원티드 지원서.md`에는 7개 제출 항목과 유의사항이 있다. 아래 Lindy 기능군은 제품 확장 검증 목록이지 전부를 이번 제출 필수로 확정한 목록이 아니다. 사용자에게 Lindy 테스트 계정이 없어 직접 비교는 미실행으로 두고 사수 변경 전·후를 비교한다. QA 설정 경고를 기록한 뒤 테스트를 계속 진행하도록 승인받았다.

## 제출 필수 증거

각 기능에 요구사항 ID, 구현 파일, 테스트 ID, 실제 연동 결과, 미해결 위험을 연결한다. 화면만 있거나 외부 연동이 모의 처리된 경우 완료로 표시하지 않는다. 우승은 통제 가능한 완료 조건이 아니므로 기능 완주·정확도·안전성·심사 시연 재현성을 검증한다.

| 기능군 | 검증할 실제 시나리오 | 필요한 외부 조건 |
|---|---|---|
| 개인/팀 Q&A 및 결정 흐름 | 다른 부서 근거 차단, 원칙 인용, 결정 카드, 정정 원장 | 동의한 테스트 Slack 사용자/채널 |
| 이메일 | 수신→분류→초안→승인→단일 발송 | 테스트 계정, 허용 수신자 |
| 일정 | 충돌 탐지→제안→승인→예약·변경·취소 | 테스트 캘린더/참석자 |
| 회의 | 참여·동의→전사→요약→후속 실행 | 테스트 회의 및 연동 계정 |
| Skills/Routines | 소유권·버전·트리거·중지·dry-run·실행 | 테스트 목적지와 시간대 |
| Files/Artifacts | 갱신·근거·버전·권한 회수 후 차단 | 합성 파일 세트 |
| 연동/MCP/승인 | 최소 권한·토큰 회수·승인 payload 변경 시 거부 | 테스트 연동 및 승인 범위 |
| 운영 복구 | 중복 수신·실행 중단·lease 만료·늦은 완료 차단 | 격리 DB·실패 주입 환경 |

## 분류 개선의 첫 검증 묶음

- 기존 64문장 결과(41/64, 결정 재현율 9/16)를 변경 전 기준으로 보존한다.
- 규칙 부정 판정이 모델 검토를 막는 구조를 검토한다. 변경 후보는 규칙을 정량 신호로만 쓰고 유효 항목의 의미 분류를 기존 모델 게이트웨이에 맡기는 것이다. 비용 증가와 confidence=null 승격 정책을 PRD/ADR에 먼저 반영해야 한다.
- L1: 비후보 입력도 모델 검토, 완료 사실/실행/미결 결정 구분, 실패 시 unclassified, 낮거나 없는 confidence 처리, 삭제된 항목 미호출.
- L2: 게이트웨이 실패·스키마 실패·재시도 및 DB 오류.
- 실제 모델 평가: 같은 64문장으로 전후 비교하되 회귀 데이터라고 표시한다. 새로운 동결 데이터의 독립 평가와 구분한다. 정밀도·재현율·오탐·토큰·지연을 함께 보고한다.
- L3~L5: 실제 대시보드→카드→결정→원장 흐름과 비공개 근거 차단. 실행하지 않은 레벨은 미실행으로 남긴다.

## Lindy 직접 비교

계정 접근 확인 전에는 Lindy 실행 결과를 만들지 않는다. 동일 합성 데이터·권한·업무 성공 조건을 사용하고 제품 버전/설정/시간을 기록한다. 분류 라벨 정확도만으로 기능 전체 우월성을 판정하지 않는다. 승인 없는 발송, 누락, 중복 실행, 권한 누출은 별도 실패로 기록한다. 설정 불가능한 기능은 0점으로 임의 환산하지 말고 비교 불가 이유를 기록한다.

## 사전 검사 기록

QA 스킬의 Bash 래퍼는 Windows에서 `/c/Users/.../lib/qa` 모듈 경로를 해석하지 못해 실패했다. 같은 검사 모듈을 Windows 절대 경로로 직접 실행한 결과:

- dead-code / completeness / shell-escape / wiring: 지적 0건.
- config-audit: `bkit.config.json not found or invalid JSON` 1 CRITICAL.

이는 QA 도구 설정 문제이며 제품의 보안 결함으로 해석하지 않는다. 사용자가 경고를 기록하고 계속 진행하도록 승인했다. 분류 변경과 실제 모델 비교 실행 결과는 [분류 개선 QA 보고서](classification-recall.qa-report.md)에 기록한다. 이전 요청의 통과 기록을 이번 확장 구현의 통과로 재사용하지 않는다.
