# 확대 테스트 및 실제 분류 평가

> 이 문서는 변경 전 평가 기록이다. 2026-09-12 후속 누락 개선 결과(62/64)는 [분류 개선 QA 보고서](../05-qa/classification-recall.qa-report.md)를 참고한다. 아래 원시 결과와 초기 실패 수치는 보존한다.

실행일: 2026-09-12. **단위 테스트는 통과하지만 실제 분류 품질 평가는 실패했다.** Lindy 대비 우월성이나 운영 준비 완료를 의미하지 않는다.

## 실행 기록

| 검증 | 결과 | 범위/제한 |
|---|---|---|
| `npm run lint` | 종료 코드 0 | ESLint |
| `npm run build` | 종료 코드 0 | 프로덕션 컴파일·TypeScript·페이지 생성 |
| `npm test` | 26파일, 421개 통과 | 기존 148개 + 신규 273개; 외부 API 없는 회귀 테스트 |
| `npx vitest run --config vitest.eval.config.ts` | 41개 일치, 23개 불일치, 종료 코드 1 | 합성 문장 64개, 실제 분류 파이프라인과 Groq; 업무 DB/큐는 모의 처리 |

SQL 검증은 임시 설치한 `@electric-sql/pglite@0.5.8`, `@electric-sql/pglite-pgvector@0.0.9`를 사용한다. 실제 마이그레이션을 실행하되 pg_cron/pg_net용 0004는 제외한다. 운영 Supabase에 이번 마이그레이션이 적용됐다는 뜻은 아니다. 조직 4개×부서 3개, 사용자 24명, 항목 72개이며 사용자×대상 부서×7종 테이블/검색 검증 = 2,016개다. 인증 서버·PostgREST·실제 벡터 검색 품질은 별도 검증 대상이다.

## 발견하고 수정한 버그

실행 요청 정규식이 `해s*주세요`처럼 백슬래시를 빠뜨려 “공유해 주세요” 등의 공백 표현을 놓쳤다. 먼저 확장 테스트를 실행하여 공백/탭/줄바꿈 실패 32개를 확인한 뒤 `\s*`로 수정했다. 초기 총 실패 33개 중 나머지 1개는 짧지만 유효한 라벨 이유에 대한 테스트의 임의 길이 제한이어서 공백 아닌 이유 존재 검사로 정정했다. 정답 라벨을 모델 결과에 맞춰 바꾸지 않았다.

## 실측 품질 — 잠정 정답 기준

| 구간 | 정확도 | 결정 정밀도 | 결정 재현율 | 결정 후보 재현율 |
|---|---|---|---|---|
| 전체 64개 | 41/64 = 64.1% | 9/9 = 100% | 9/16 = 56.3% | 10/16 = 62.5% |
| 개발 32개 | 22/32 = 68.8% | 6/6 = 100% | 6/8 = 75.0% | 6/8 = 75.0% |
| holdout 32개 | 19/32 = 59.4% | 3/3 = 100% | 3/8 = 37.5% | 4/8 = 50.0% |

정밀도 100%는 결정으로 분류한 9건에 한정되며 일반화할 수 없다. 결정 16건 중 7건을 놓쳤다. 후보 단계가 6건을 놓쳐 이후 LLM이 해당 결정 여부를 검토할 기회도 없었다. 불일치 23건은 결정→정보 6건, 잡담→정보 15건, LLM 단계 2건(C020 정보→액션, C039 결정→액션)이다.

실제 호출 모델은 `openai/gpt-oss-20b`, 16회, 입력 5,505/출력 6,190토큰이다. 합성 데이터만 전송했으며 업무 테이블 삽입·카드 생성·Slack 발송은 모의 처리했다. `llm_calls` 기록은 기존 게이트웨이로 시도했으나 DB 저장 성공은 이 실험이 확인하지 않는다.

## 정확한 해석과 다음 작업

1. 64문장은 독립 검수되지 않은 합성 잠정 정답이다. holdout도 작성자가 동일하므로 외부 블라인드 검증을 대신하지 않는다. 실제 업무 분포의 정확도로 발표하지 않는다.
2. 우선 미결 선택/승인 표현을 놓치는 후보 단계와 완료 사실/실행 요청의 경계를 재설계해야 한다. 현재 데이터에만 맞춘 정규식 추가로 성능을 인증하지 않는다. 개발 데이터로 개선 후 새로운 독립 평가 세트를 동결한다.
3. 마스킹·미동의 스킵·인용 변형·SQL 권한 검증을 늘렸지만, 인용의 의미적 뒷받침과 전체 카드 생성/알림의 실제 품질은 아직 이 평가에 포함하지 않았다.
4. 사용자/업무 담당자가 라벨과 이유를 검수하고 애매한 사례를 조정해야 한다. Lindy와의 비교는 동일 시나리오를 실행할 테스트 계정이 필요하다.
5. 이전 [설계 위험 보고서](quality-design-review.md)의 이벤트 재시도, 워커 복구, 잔여 쓰기 권한 문제는 이번 분류 수정으로 해결되지 않았다. 배포·보안 완결 선언은 보류한다.
