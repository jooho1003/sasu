# 사수(SASU) UI/UX 개선 및 검증 기록

- 일자: 2026-09-17 (Asia/Seoul)
- 기준 감사: [`../ux-audit-2026-09-17/README.md`](../ux-audit-2026-09-17/README.md)
- 사용자 이야기: 심사자와 실제 팀원이 사수에서 결정의 근거를 확인하고, 과거 결정까지 추적한 뒤, 같은 질문이 부서 맥락에 따라 어떻게 달라지는지 신뢰할 수 있게 비교한다.

## 1. 결과 요약

초기 감사의 신뢰성 P0 두 건은 수정했다. 영업 카드의 충돌 결정은 이제 외주사 가격·재입찰 원칙으로 직접 연결되고, 근거가 없는 준비 답변은 무관한 인용 대신 `refused` 상태와 `근거 없음`을 표시한다. 영업의 가격 답변처럼 두 사실을 함께 주장하는 답은 요청과 원칙을 각각 인용한다.

쇼케이스 데이터 오염은 새 오염을 막는 실행 가드와 읽기 전용 감사 도구까지 적용했다. 기존 데이터는 결정 원장의 append-only 원칙 때문에 임의 삭제하지 않았다. 아래 5절의 별도 데이터 결정을 거쳐야 한다.

## 2. 구현한 개선

### 근거 신뢰성과 게스트 핵심 흐름

- 외주사 12% 인상 안건과 직접 관련된 `10% 이상 인상 시 재입찰 검토` 결정을 시드하고, 카드에 충돌 이유를 구체적으로 표시했다.
- 답변 시드를 `item_ids[]` 기반으로 바꾸어 한 답변이 복수 근거를 인용할 수 있게 했다.
- 근거가 없는 개발 부서의 가격·인터뷰·외주사 질문은 `refused`로 표시하고 인용을 0개로 유지한다.
- 답변 화면에 `같은 질문을 다른 부서에서 보기`를 추가하고 질문을 유지한 채 부서를 전환한다.
- 게스트 전 화면에 `결정 발견 → 근거 확인 → 과거 결정 → 같은 질문` 4단계 진행 표시를 유지한다.
- 카드 → 충돌 원장 하이라이트 → 카드 복귀 → 같은 질문 비교로 이어지는 CTA를 추가했다.
- 부서 선택에서 영업 사수를 `추천 · 90초 핵심 데모`로 강조했다.
- 결정 카드 상단에 마감, 결정 권한, 가시성, 근거 수, 상태를 구조화해 표시한다.

### 모바일 탐색과 긴 목록

- 부서 내비게이션을 핵심 4개 메뉴와 `더보기`로 재구성했다.
- 실제 기능과 맞지 않던 `역할` 메뉴명을 `문서 평가`로 변경했다.
- 준비 질문에 `1/6` 형태의 위치와 이전/다음 버튼을 추가했다.
- 대시보드는 첫 10건, 원장은 첫 10건, 질문 기록은 최근 5건을 기본으로 표시하고 단계적으로 더 볼 수 있게 했다.
- API 목록 조회에 최대 100건 제한을 적용했다.
- 관리자 멤버 표는 모바일에서 이름·부서·역할·동의·Slack 상태가 보이는 카드로 전환했다.
- 모바일 메뉴의 접근 가능한 이름을 열림 상태에서 `메뉴 닫기`로 교정했다.

증거: [모바일 관리자 멤버](../../../outputs/ux-improvement/admin-members-390.png)

### 첫 설정·업로드·로그인 안내

- 세팅 상단에 완료 단계와 현재 차단 원인을 표시하는 4단계 체크리스트를 추가했다.
- 자료 검토 업로드 버튼 앞에 파일, 참여자/유형, 동의 확인 상태를 표시했다.
- 로그인 화면에 초대 이메일, 스팸함, 멤버십 확인 도움말을 추가했다.
- 범용 준비 답변을 `범용 AI 답변 예시 · 사전 작성`으로 명시했다.

### 쇼케이스와 배포 안전장치

- 쓰기 E2E는 `E2E_ALLOW_SHOWCASE_WRITES=1`을 명시하지 않으면 기본적으로 건너뛴다. 격리된 QA 흐름은 기존 `scripts/review-qa.mjs`를 사용한다.
- `npm run audit:showcase`는 본문을 출력하지 않고 ID와 건수만으로 QA/E2E 흔적을 검사한다.
- `npm run check:demo-release`는 `/demo`의 관리자·예고편 링크 노출과 대상 URL의 200 응답을 검증한다.
- `/demo`, `/demo/admin`, `/demo/d/[dept]`를 런타임 렌더링으로 명시해 빌드 시점 기능 플래그 고정을 피했다.

## 3. 검증한 유저 플로우

| 플로우 | 검증 결과 |

| `/demo` → 추천 영업 사수 → 결정 카드 | 추천 시작점, 핵심 메타데이터, 4단계 진행 표시 확인 |
| 결정 카드 → 충돌 원장 | 외주사 가격/재입찰 관련 결정으로 이동하고 대상 행 하이라이트 확인 |

| 모바일 부서 탐색 | 핵심 메뉴 4개와 더보기, 질문 이전/다음, 메뉴 접근성 이름 확인 |
| 모바일 조직 관리자 → 멤버 | 잘리지 않는 카드 목록과 동의·Slack 상태 확인 |
| `/demo` 제출 동선 | 관리자와 채용 예고편 링크 및 대상 200 응답 확인 |

## 4. 실행 검증

- `npm test` → 82개 파일, 1,029개 테스트 통과
- `npx tsc --noEmit` → 통과
- `npm run lint` → 통과
- `npm run build` (`SASU_ORG_ADMIN_MODE=readonly`, `SASU_TRAILER_PUBLISH_ENABLED=true`) → 통과
- `npx playwright test tests/e2e/guest.spec.ts tests/e2e/ui-refresh.spec.ts --project=chromium` → 10/10 통과
- `npm run check:demo-release` → `/demo`, `/demo/admin`, 부서 채용 예고편 모두 200
- 390px 실화면 재확인 → 추천 시작점, 카드, 답변, 거절, 관리자 멤버 화면 이상 없음
- Vercel 연결 프로젝트의 production 환경에서 필요한 기능 플래그 키 존재를 확인했다. 값은 기록하거나 노출하지 않았다.

Graft와 Archify는 이 환경에 도구·명령이 없어 실행하지 못했다. 대신 변경 라우트, import, 데이터 조회, CTA 연결을 직접 추적하고 실제 브라우저 흐름 및 E2E로 실행 경로를 검증했다. 누락 범위는 자동 의존 그래프와 구조 시각화 산출물이다.

## 5. 아직 사용자 결정이 필요한 항목

읽기 전용 감사에서 현재 쇼케이스 조직에 다음 흔적이 확인됐다.

| 패턴 | 확인 건수 |
|---|---:|
| `[QA-` item | 2 |
| `[QA-` answer | 3 |
| `[합성 QA` item | 10 |
| `[합성 QA` decision | 3 |
| `E2E-` item | 22 |
| 의심 부서 | 1 |

자동 삭제는 수행하지 않았다. 특히 결정은 append-only라 삭제·수정으로 정리하면 프로젝트 불변식을 위반한다. 권장안은 **새로운 깨끗한 쇼케이스 조직을 만들고 제출·시연 계정을 그 조직으로 전환**하는 것이다. 기존 조직은 내부 QA 이력으로 격리한다.

## 6. 후속 개선 백로그

이번 구현에서 아직 남긴 항목은 기록 보존 화면의 단계형 재설계, 문서 요약 중복 제거, 채용 예고편 검토 항목 그룹화, 개인정보 안내의 모바일 목차, 로그인 상태별 `/admin` 안내 분리다. 이들은 핵심 게스트 신뢰 흐름보다 우선순위가 낮아 다음 반복 작업으로 남겼다.

운영 배포는 수행하지 않았다. 배포 전에는 새 쇼케이스 조직 여부를 결정하고, 배포 URL에서 `npm run check:demo-release -- <URL>`과 두 E2E 파일을 한 번 더 실행해야 한다.
