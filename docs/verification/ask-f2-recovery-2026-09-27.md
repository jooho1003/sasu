# ASK F2 운영 재시험과 근거 복구 — 2026-09-27

- PR #10 머지 커밋 `5451b25`의 Vercel 배포 상태 `success` 확인 후 파일럿 웹 ASK에서 동일 상태 질문을 재시험했다. 답변은 `refused`, `error_code=citation_invalid`였다. 원문 질문은 이 보고서에 복사하지 않는다.
- 운영 SQL에서 같은 질문자의 권한으로 `search_topic_items_as`를 실행했다. 상위 8개 중 첫 항목은 9/15 보류 회의록이며, 나머지 7개는 합성 QA 질문 기록이었다. 따라서 검색 누락보다는 모델의 인용 선택 실패가 재현된 지점이다. 모델 응답 본문은 저장하지 않아 개별 선택 실패의 세부 이유는 확인할 수 없다.
- 답변 파이프라인은 모델이 인용을 확정하지 못할 때, 권한 검색으로 찾은 날짜 있는 상태 기록에 안건 단어가 모두 들어가고 명시적 상태 서술이 있는 경우에만 해당 원문 문단을 제시한다. 현재 상태는 확정하지 않는 고정 안내를 유지한다. 질문형 기록, 다른 안건, 시각 없는 기록은 이 경로에 넣지 않는다.
- 새 SQL 0056은 `search_topic_items_as`에서 비활성 출처를 제외한다. 운영 SQL Editor에서 동등한 함수 변경을 적용했고 `active_guard=true`, `member_execute=true`를 확인했다. CLI 인증 부재로 0055·0056은 `supabase_migrations` 이력에 기록되지 않았다. 추후 CLI 연결 시 두 마이그레이션을 정상 적용할 수 있도록 `create or replace`를 사용한다.
- 단위 회귀 38건, 전체 Vitest 1,414건, lint 차단 0(기존 문구 경고 77건), 프로덕션 빌드 성공. 빌드는 실제 비밀값 없이 공개 Supabase 변수에 임시 자리표시값을 설정해 검증했다. API 세션 기반 RLS 자동화는 DB 환경값 부재로 미실행이다.
- 이전 [Graft·Archify 검증](ask-f2-retrieval-2026-09-27/README.md)의 검색·답변 의존 관계를 참고했다. 이번 복구 경로는 기존 `answerQuestion` 안의 분기이며 새 의존 관계는 없다. 현재 환경에서는 두 도구 실행 파일을 찾지 못해 이 후속 변경에 대한 새 그래프·도식 생성은 누락됐다.
