# Lindy 기능 흡수 및 SASU 격차 분석

조사일: 2026-09-12. 결론: **현재 SASU가 Lindy보다 좋다고 말할 근거는 없다.** 기능 폭은 SASU가 부족하고, 결정 분류 자체도 이번 잠정 정답 평가에서 재현율 56.3%다. Lindy 계정에서 같은 사례를 실행하지 않아 상대 정확도·속도·비용은 미측정이다.

## 조사 방법과 판정 기준

Lindy 공식 홈페이지, Teammate·Skills·Routines·Files·Artifacts·Meeting Library·연동·MCP·Credentials·이메일·일정 문서를 조사하고 SASU 구현/PRD와 대조했다. 아래는 공개 **기능군** 목록이지 1,000개 이상 연동의 개별 액션 전수 검증이 아니다. 홈페이지 수치는 공급자 주장이다. Skills 등은 점진 배포될 수 있어 계정별 제공 여부가 다르다. [공식 제품 소개](https://www.lindy.ai/), [문서 목록](https://docs.lindy.ai/llms.txt), [Skills](https://docs.lindy.ai/teammate/skills).

`부분 구현`은 코드가 있다는 뜻이지 실사용 품질 인증이 아니다. 기능 흡수 완료는 동일한 정상·권한 거부·재시도·실패 시나리오를 실제 연동 환경에서 통과해야 한다. Lindy에 결정 원장이 없다는 식의 부재 주장은 이번 조사로 확정할 수 없다.

## 기능군 대조

| Lindy 공개 기능군 | SASU 현재 상태 | 흡수 완료에 필요한 검증 |
|---|---|---|
| Slack 개인 DM/팀 채널 컨텍스트 | 이벤트·Q&A·카드 경로 부분 구현, 부서 SQL 권한 검증 | 개인과 팀 컨텍스트가 섞이지 않는 멀티턴·연동 E2E |
| 이메일 분류·초안·후속 조치 | 해당 사용자 OAuth·실행 흐름 미구현 | 수신→라벨→근거 있는 초안→승인→중복 없는 발송 |
| 일정 탐색·회의 예약 | 미구현 | 시간대·충돌·변경·취소·중복 요청 검증 |

| Artifacts·보고서·문서 생성 | 범용 산출물 실행 흐름 미구현 | 근거·버전·다운로드·비밀 데이터/실행 격리 |

보안 비교 시 유의: Lindy도 개인/공유 범위와 도구 승인을 제공한다. MCP의 도구별 승인과 raw credential을 코드에서 사용하는 경로는 같은 보호 범위가 아니다. 따라서 모든 실행이 자동 승인 대기한다고 일반화하거나, SASU만 권한을 인지한다고 주장하면 안 된다. 위 MCP·Credentials 문서의 경로별 제약을 기준으로 비교한다.

## 권장 설계 순서 — 아직 구현 승인이 아니라 후속 설계 입력

1. **연결/실행 기반:** 사용자별 연결·최소 권한·토큰 회수, 실행 원장, 승인 시 payload 고정, dry-run, 멱등 키, 재시도/lease/실패 상태. 승인 뒤 입력이 바뀌면 재승인한다. 현재 이벤트 재시도 유실 및 jobs 복구 위험도 먼저 해결한다.
2. **핵심 업무 완주:** Slack·Notion에 이메일/일정과 회의 후속 실행을 더한다. 각 연동은 읽기→제안→승인→쓰기→외부 결과 확인까지 검증한다. 외부 서비스 개통/발송에는 별도 설정과 권한이 필요하다.
3. **재사용 자동화:** Skills(버전·입출력·허용 도구·평가 세트), Routines(트리거·목적지·중지), Files(소유권·갱신), Artifacts(근거·버전)를 공통 실행 기반에 얹는다. UI부터 추가하면 승인/감사 로직이 중복될 위험이 있다.
4. **연동 폭 확대:** MCP 카탈로그와 조직 정책을 도입하되 도구 설명을 신뢰된 명령으로 취급하지 않는다. 도구별 권한·승인·데이터 반출 범위를 검증한다. 개별 연동/액션 목록은 버전 관리하고 미검증 항목을 표시한다.
5. **SASU 특화 고도화:** 부서 원칙 → 미결 결정 → 담당자 카드 → 근거/결정 원장 → 후속 실행의 연결을 개선한다. 이는 차별화 가설이며, 경쟁 우위는 동일 과제의 누락률·불필요 알림·처리 시간·권한 누출·비용으로 검증한다.

기술 스택 전체 교체나 다른 LLM 제공자로의 전환을 이번 조사만으로 권하지 않는다. 공통 권한 판정은 계속 `can_see()`, 텍스트 모델 호출은 `llm.structured()` 하나로 유지한다.

## 다음 검증 게이트

- 동결된 독립 검수 데이터로 PRD의 결정 재현율 목표를 충족하고, 정밀도/잡담 오탐을 함께 보고한다.
- 인용 문자열 존재뿐 아니라 **인용이 주장과 추천을 실제로 뒷받침하는지** 별도로 평가한다.
- 연결 토큰 회수·부서 이동·동의 철회·중복 이벤트·워커 중단 후 재개·승인 후 입력 변경을 테스트한다.
- Lindy 테스트 워크스페이스에서 동일 시나리오를 실행하기 전까지 기능/품질 우월성 표시는 하지 않는다.
- 9/20 제출 범위와 장기 흡수 목표는 구분한다. 일정 배정은 미확정이며 PRD §8의 기존 컷 라인이 유효하다.
