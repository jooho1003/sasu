## 1. 점검 결과 — 지금 무엇이 문제인가

방법: (a) 3100 검증 서버(`SASU_VERIFY_BUILD=1` 빌드)의 공개 데모 18개 화면을 실제 브라우저로 열어 본문 텍스트 전체와 스크린샷(1440·390)을 수집 (b) 로그인이 필요한 화면·슬랙 메시지·API 오류 문구는 소스 전수 조사(`app/**`, `components/**`, `lib/**`, 43개 라우트의 한국어 오류 문자열 217건) (c) 9/17 UX 감사([`ux-audit-2026-09-17`](../verification/ux-audit-2026-09-17/README.md))와 겹치는 항목은 제외.

주의: 3100 서버는 이전 빌드라 작업 트리의 미커밋 변경(phase 25·26 일부)은 반영되지 않았다. 문구 판정은 소스 기준으로 다시 확인했다.

### 1-1. 한 줄 결론

시각 완성도·반응형·인용 UI는 좋다. 그러나 **말이 어렵다.** 메뉴 10개 중 5개(원장·음성·자료 검토·문서 평가·기록 보존·세팅)가 중2에게 뜻이 통하지 않고, 핵심 화면의 이름표(결정 권한·공개 범위·근거 인용·정정 이력)와 데모 안내(합성 데이터·시드 결과 확인·안전 체험·append-only·권한 인지)가 서비스 내부 용어를 그대로 쓴다. 문체는 화면마다 갈리고, 영문 상태값이 한국어 문장에 그대로 끼어 나오는 자리가 4곳 있다. LLM이 만드는 문장에는 "쉽게 써라"는 지시가 아예 없다.

### 1-3. 문체·호칭·표기 불일치

- **문체**: 문서 어시스턴트 로딩은 "불러오고 있어요" 다음 줄이 "확인하고 있습니다". 예고편은 해요체, 설정·관리자는 합쇼체. LLM 답변은 합쇼체.
- **호칭**: 같은 `role === "lead"`를 대시보드·카드·문서 평가·설정은 "팀장", 관리자·자료 검토·기록 보존·예고편은 "부서장"으로 쓴다.
- **브랜드**: "슬랙 기록"(대시보드) ↔ "Slack 연결"(설정) ↔ "Slack 워크스페이스"(관리자).
- **버튼**: 명사형(`결정` `삭제`), "-기"형(`매직링크 받기`), 완전문형(`미동의 멤버에게 동의 요청 보내기`), 데모 접미형(`설정 저장 체험`) 네 가지가 섞여 있다. 파괴적 버튼이 가장 짧고(`삭제` `철회`) 안전한 버튼이 길다(`원본 보호 설정 저장`) — 위험도와 길이가 거꾸로다. 진행 중 상태 `"…중…"`만 일관된다.

### 1-6. LLM 문장 — 문체 지시 부재

`lib/llm.ts:36`의 전역 지시는 필드 순서(citations 먼저)만 정한다. 답변·카드·문서 요약·회의 정리·예고편 프롬프트는 "한국어로 쓰라"와 금지어(합격·불합격·추천·평가·적합도)만 있고, **독자 수준·문장 길이·용어 수준·문체 지시가 없다.** 사람이 쓴 문구를 쉽게 바꿔도 카드 배경·답변 본문이 어려우면 화면은 그대로 어렵다.

## 2. 기준 — "중2도 이해하고 쓴다"를 검사 가능한 규칙으로

"중학교 2학년"은 뜻을 정한 기준이지 검사할 수 있는 기준이 아니다. 아래 7개 규칙으로 바꾼다. 규칙마다 검사 방법이 있다.

| # | 규칙 | 검사 방법 |
|---|---|---|
| W1 | **금지어 사전에 있는 말을 쓰지 않는다.** 대체어가 없으면 처음 한 번 풀어 쓴다. 괄호 설명 대신 "…(우리 회사의 슬랙 공간)"처럼 쉼표 없이 이어 쓴다 | `scripts/check-wording.mjs`가 UI 문자열을 훑어 파일:줄과 대체어를 출력한다(§5) |
| W2 | **영어 단어·약어를 쓰지 않는다.** 예외: 파일 확장자를 소문자 점 표기로(`.vtt 파일`), 고유명사(슬랙·노션·구글 미트는 한글). 화면에 나가는 상태값은 항상 한글 이름표를 거친다 | 검사기의 영문 대문자 약어 패턴 + `lib/labels.ts`의 전수 이름표 타입(§5-2) |
| W3 | **한 문장 한 뜻. 본문 40자, 제목 20자, 버튼 8자 안.** 넘으면 문장을 나눈다 | 검사기가 60자 초과 문장을 경고로 출력한다(차단 아님) |
| W4 | **문체 하나.** 안내·오류·빈 상태는 "-합니다/-하세요". 예고편 가상 동료 말풍선만 "-해요"(§0-1). 한 화면에 두 문체를 섞지 않는다 | 검사기가 같은 파일에서 "-어요/-아요/-해요" 종결과 "-습니다/-세요"가 함께 나오면 경고. 예고편 컴포넌트는 예외 목록 |
| W5 | **버튼은 "무엇을 하는지"가 보이게 동사로 끝낸다.** 형태는 `동사+기`(결정하기·미루기·올리기). 파괴적 버튼은 대상을 붙인다(`이 예고편 지우기`). 진행 중은 `…하는 중…` 유지 | 코드 리뷰 체크리스트(§7). 검사기는 `<button>` 텍스트가 명사 1어절이면 경고 |
| W6 | **오류·빈 상태는 두 문장.** ① 무엇이 안 됐나(또는 왜 비었나) ② 지금 할 수 있는 것. "오류가 발생했습니다"·영문 코드·상태값 금지(PRD §6-10 유지) | 검사기가 `오류가 발생` 문자열과 `${…status}` 템플릿을 잡는다 |
| W7 | **LLM 문장도 같은 기준.** 모든 텍스트 생성 프롬프트에 공통 문체 블록을 붙인다(§6). 원문 인용(`quote`)은 그대로 두고 생성 문장에만 적용 | 프롬프트 빌더 단위 테스트 + 준비된 질문 6개·카드 3개 샘플 출력을 검사기에 통과시켜 기록 |

**허용 목록(대체하지 않는 말)**: 결정 · 근거 · 원칙 · 기록 · 카드 · 대시보드 · 메뉴 · 링크 · 파일 · 채널 · 멤버 · 동의 · 마감 · 담당자 · 질문 · 답변 · 문서 · 회의 · 검색 · 저장 · 확정 · 초대 · 설정 · 점수 · 기준표. 이 말들은 교과서·일상에서 쓰이고, 사수의 핵심 개념(결정·근거·원칙·기록)이라 그대로 둔다.

**바꾸지 않는 고정 문구(불변식·법적 문구)**: "이 채널의 부서 공개 기록만 참고했습니다" · "내 권한 범위 안의 부서 기록만 참고했습니다"(ADR-015·050) → 뜻을 유지한 채 쉬운 말로 바꾸되 **PRD §6-5를 먼저 고친 뒤** 바꾼다(§9). "조직 관리자 권한만으로는 부서 내용을 볼 수 없습니다"는 절대 문장 금지 규칙에 따라 뜻을 유지한다. 동의 전문(`lib/consent.ts`)은 법적 고지라 **문장 단위로 뜻이 같은지 팀장이 확인한 뒤**에만 바꾼다(step 5).

## 5. 강제 장치 — 규칙이 문서에만 있으면 다시 어려워진다

### 5-1. 문구 검사기 `scripts/check-wording.mjs` + `lib/wording-check.ts`

- 핵심 로직은 `lib/wording-check.ts`(순수 함수: 문자열 목록 → 위반 목록)에 두고 TDD로 만든다. `scripts/check-wording.mjs`는 파일을 읽어 문자열을 뽑아 넘기는 얇은 껍데기.
- 대상: `app/**/*.tsx`의 JSX 텍스트·문자열 리터럴, `components/**/*.tsx`, `lib/slack/**`, `lib/consent.ts`, `lib/demo-access.ts`, `lib/org-admin.ts`, `lib/trailer-invite.ts`, `lib/trailer-assessment.ts`, `components/trailers/views.tsx`, `app/api/**/route.ts`의 `error:`/`message:` 값. 제외: 테스트, `scripts/`, 주석, `console.*` 인자, 코드 식별자.
- 사전: `scripts/wording/terms.json` — `{ term, replacement, reason, allow_in: [glob] }`. 개인정보·동의 문서는 병기 허용(`allow_in`).
- 검사: W1 금지어(차단) · W2 영문 대문자 2자 이상 약어와 영문 단어(차단, 허용 목록 `Slack`은 관리자 설치 파일만) · W3 60자 초과 문장(경고) · W4 문체 혼용(경고) · W6 `오류가 발생`·`${…status}`·`${…state}` 템플릿(차단).
- 예외 표시: 같은 줄 끝 `// wording-ok: 이유`. 이유 없는 예외는 위반.
- 출력: `파일:줄 · 원문 일부 · 금지어 → 대체어`. `--report`는 종료 코드 0, 기본은 위반 있으면 1. `npm run check:wording`. §0-7에 따라 step 7 뒤 `"lint": "eslint . && node scripts/check-wording.mjs"`.

### 5-2. 상태 이름표 SSOT `lib/labels.ts`

- `lib/contracts.ts`의 enum마다 `Record<Enum, string>`을 **전수**로 정의한다. TS가 값 하나라도 빠지면 컴파일을 막는다. 대상: 카드 상태(`open`·`decided`·`deferred`·`rejected`·`needs_review`·`merged`…) · 답변 상태 · 분류 라벨 5개 · visibility 2개 · 자료 검토 상태 · 초대 상태 9개 · 예고편 상태 · 노션 수집 상태 · job 상태(관리자 화면).
- 화면과 API 오류 메시지는 enum 값을 직접 문자열에 넣지 않고 `label(kind, value)`를 거친다. §1-4의 4곳을 이것으로 고친다.
- 테스트: 모든 라벨이 한글·8자 이내·금지어 0.

### 5-3. 리뷰 체크리스트 (`docs/wording-guide.md` 끝에)

새 화면·문구 PR마다 7줄: 금지어 0 · 영문 0 · 문체 하나 · 버튼 동사형 · 오류 두 문장 · 빈 상태 두 문장 · 이름표는 `lib/labels.ts`. `scripts/hooks/`에 넣지 않는다(검사기가 lint 체인에서 대신 돈다).

## 6. LLM 문장 — 공통 문체 블록

`lib/llm.ts`의 전역 지시(`:36`, citations 우선) 뒤에 한 블록을 더 붙인다. 모든 `llm.structured()` 호출에 자동 적용된다.

```
문체 규칙: 중학생도 이해할 수 있는 쉬운 한국어로 씁니다. 한 문장은 한 가지 뜻만 담고 40자를 넘기지 않습니다.
전문 용어·한자어 사무 용어·영어 단어·약어를 쓰지 않습니다(예: 원장→결정 기록, 인용→원문 근거, 검토→확인, 산정→계산).
"-합니다/-하세요"로 끝맺습니다. 원문을 그대로 옮기는 quote 필드는 바꾸지 않습니다.
```

- 예고편 생성(`lib/trailer-generation.ts`)만 가상 동료 말풍선 필드(`dialogues[].question`·NPC 대사)에 "-해요" 허용을 덧붙인다.
- 기존 금지어(합격·불합격·추천·평가·적합도)는 그대로.
- 검증: 프롬프트 빌더 테스트(블록 포함 여부) + 데모 준비 질문 6개·카드 3개·문서 요약 2개를 실제 호출해 결과를 `scripts/check-wording.mjs --text`로 검사한 기록. 인용 검증(문자열 포함)은 quote를 건드리지 않으므로 영향 없음 — `tests/pipeline/answer.test.ts`의 인용 케이스가 그대로 통과해야 한다.
- 위험: 120b 모델이 규칙을 지키지 않아도 답변을 막지 않는다(인용 검증만 막는다). 문체는 품질 지표이지 게이트가 아니다. 어긴 비율을 검증 기록에 남기고, 30% 넘으면 PRD §10 #21 순서(프롬프트 강화 → 모델 교체)를 따른다.
