# 개발 회고 자동화 설계 — 흔적을 모아 인용 기반 회고를 만들고, 사수 안에서 날짜별로 본다

- 작성일: 2026-09-19 · 상태: **2026-09-19 사용자 제안값 7개 확정 · 구현 착수 승인 / 운영 반영 미실행. 9/20 제출 범위에 넣지 않는다.**
- 범위 원천: [PRD §3-6·§8](../PRD.md), 구조: [ARCHITECTURE §6-4](../ARCHITECTURE.md), 선택 이유: [ADR-063](../ADR.md)
- 사용자 요구(9/19): 하루 동안 무엇을 찾아보고 무엇을 공부했는지 회고를 노션·블로그에 쓰는 일 자체가 귀찮다. 크롬에서 찾아본 것, 대화 세션(Claude·Codex)에서 물어본 것, 메모리·CLAUDE.md 같은 설계 파일의 변경, 처리된 것(커밋·결정)을 자동으로 파악해 **오늘의 회고를 만들어 주고**, 회사 기여·마케팅에 쓸 수 있게 노션·블로그 형태로 내보내며, **사수 안에서 사용자별로 어느 날짜에 어떤 주제의 회고를 했는지 빠르게 훑어볼 수 있어야** 한다.
- 현재 기능: 사수에는 결정 원장·묻기·자료 검토함(업로드 → 검토 → 확정 → 인용 요약, ADR-054)이 운영 중이다. 회고·개인 활동 수집·노션 쓰기·공개 링크는 모두 신규 설계다. 이 문서는 상위 문서를 바꾸지 않는다 — 승인되면 PRD §3-6·§8 → ARCHITECTURE §6-4 → ADR-063 순으로 반영한 뒤 `phases/27-daily-retro/`를 실행한다.

## 1. 현재 구조와 요구 사이의 거리

| 항목 | 현재 (코드 확인 2026-09-19) | 회고에서 생기는 문제 |
|---|---|---|
| 입력 소스 | Slack 이벤트·노션 API·전사/문서/음성 업로드. 모두 **부서의 자료** | 회고 재료는 **개인의 로컬 PC**에 있다(Claude/Codex 세션 로그, git, 메모리, Chrome). 서버가 가져올 수 없고 사용자 PC에서 뽑아 올려야 한다 |
| 가시성 | `visibility ∈ {dept, leads_only}`, 판정은 `can_see()` 하나 | "본인만"이 없다. 개인 기록에 기본 부서 공개를 적용할 수 없다 |
| 산출물 | 카드·답변·회의/문서 요약. 인용 없는 문장은 렌더하지 않는다 | 회고도 같은 규칙을 지켜야 한다 — 인용 대상이 `items`가 아니라 **활동 항목**일 뿐이다 |

| 노션 | `lib/notion.ts`는 조회만(`pages.create`·`blocks.children.append` 없음) | 노션 내보내기는 쓰기 권한과 코드가 전부 신규 |
| 열람 | 원장·검토함 목록은 부서 전체 자료 | 회고는 **사람 × 날짜 × 주제** 축이 필요하다 |

## 2. 핵심 결정 — 재료는 세 층, 파이프라인은 하나

회고는 **"오늘의 활동 항목(activity)"을 모아 인용 기반 초안을 만들고, 본인이 검토·확정하는 하루치 문서**다. 재료가 어디서 왔든 `retro_activities` 한 테이블로 정규화하고, 그 뒤는 검토함과 같은 한 파이프라인(초안 job → 검토 → 확정)을 탄다.

| 층 | 소스 | 수집 주체 | 설치 | 민감도 | 단계 |
|---|---|---|---|---|---|
| **Tier 0 — 사수 내부** | 내가 내린 결정(`decisions.decided_by`), 내가 물은 질문(`answers.asked_by`), 내가 닫은 카드(`decision_requests.assignee_id`+`closed_at`), 내가 확정한 자료(`reviewed_materials.confirmed_by`) | 서버 SQL이 본인 행만 조회 | 없음 | 낮음(이미 마스킹·권한 판정된 자료) | 1단계 |
| **Tier 1 — 로컬 개발 활동** | git 커밋(제목·변경 파일 수), Claude Code 세션 제목·입력 프롬프트 첫 줄, Codex 세션 첫 입력, 메모리 파일 변경(이름·설명), 설계 문서 변경(`docs/**`·`CLAUDE.md`·`AGENTS.md`·`.claude/**` 파일명과 증감 줄 수) | 로컬 수집기 `scripts/retro-collect.ts` | `npx tsx` 1회 + 작업 스케줄러 | 중 | 1단계 |
| **Tier 2 — 브라우저** | Chrome 방문 기록(제목·도메인·경로), 검색어 | 같은 수집기, 옵션 | 동일 | 높음 | 1단계 코드, **기본 off** |

## 3. 번들 계약 — `RetroBundle` v1

수집기의 출력이자 업로드 라우트의 입력. `lib/contracts.ts`에 Zod로 둔다.

```ts
export const RetroActivityKind = z.enum([
  "git_commit", "claude_session", "claude_prompt", "codex_session",
  "memory_change", "doc_change", "web_visit", "web_search",
  // 서버가 Tier 0에서 붙이는 종류 — 번들에는 넣을 수 없다(서버가 거부)
  "sasu_decision", "sasu_answer", "sasu_card", "sasu_review",
]);
export const RetroActivity = z.strictObject({
  kind: RetroActivityKind,
  ref: z.string().min(1).max(200),        // 커밋 hash·sessionId·경로·URL(정규화)·행 id — 같은 날 같은 kind 안에서 유일
  title: z.string().min(1).max(200),
  at: z.iso.datetime(),                   // 항목 시각(UTC)
  text: z.string().max(500),              // 마스킹된 짧은 본문(프롬프트 첫 줄·커밋 제목 등). 비어 있을 수 있다
  meta: z.record(z.string(), z.union([z.string(), z.number(), z.boolean()])).default({}),  // files_changed·domain·branch 등 스칼라만
});
export const RetroBundle = z.strictObject({
  version: z.literal(1),
  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),   // 회고 날짜(로컬 기준)
  tz: z.string().min(1).max(64),                  // "Asia/Seoul"
  collected_at: z.iso.datetime(),
  collector: z.strictObject({ name: z.literal("sasu-retro-collect"), version: z.string().max(20) }),
  activities: z.array(RetroActivity).max(500),
});
```

한도: 번들 1MB, 활동 500건, `text` 500자, `title` 200자. 수집기는 `lib/mask.ts`의 `mask()`로 먼저 가리고, 서버 RPC는 `mask_retro_text()`(SQL, `mask_review_text()`와 같은 정규식)로 다시 가린다. **마스킹 전 텍스트는 어디에도 저장하지 않는다.** 번들 파일 자체는 서버에 보관하지 않는다 — 활동 행이 전부다.

## 4. 데이터 — `retro_days` · `retro_activities` · `retro_revisions`

마이그레이션 `0046_daily_retro.sql`. 검토함(`0034`)의 상태기계·revision 낙관적 락·결정적 job id·SQL 마스킹을 그대로 옮긴다.

```sql
create table public.retro_days (
  id uuid primary key,                                   -- 클라이언트 crypto.randomUUID()
  dept_id uuid not null references public.departments,
  user_id uuid not null references auth.users on delete cascade,
  retro_date date not null,
  tz text not null default 'Asia/Seoul',
  visibility text not null default 'self' check (visibility in ('self','dept','leads_only')),
  status text not null default 'collecting'
    check (status in ('collecting','drafting','draft','needs_review','confirmed','failed')),
  status_reason text,
  collector_version text,
  activity_count int not null default 0,
  revision int not null default 0,                       -- 마지막 revision 번호(낙관적 락)
  confirmed_revision int,
  confirmed_at timestamptz,
  topics text[] not null default '{}',                   -- 확정 revision의 주제(목록·필터용 비정규화)
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (dept_id, user_id, retro_date)
);
create table public.retro_activities (
  id uuid primary key default gen_random_uuid(),
  day_id uuid not null references public.retro_days on delete cascade,
  kind text not null,                                    -- RetroActivityKind
  ref text not null,
  title text not null,                                   -- 마스킹 후
  at timestamptz not null,
  text text not null default '',                         -- 마스킹 후
  meta jsonb not null default '{}',
  source_visibility text,                                -- Tier 0만: 인용 원본의 visibility(dept|leads_only)
  excluded boolean not null default false,
  unique (day_id, kind, ref)
);
create table public.retro_revisions (
  day_id uuid not null references public.retro_days on delete cascade,
  revision int not null,
  origin text not null check (origin in ('draft','edit','confirm')),
  title text not null,
  body jsonb not null,                                   -- RetroBody (§5)
  topics text[] not null default '{}',
  edited_by uuid references auth.users,
  created_at timestamptz not null default now(),
  primary key (day_id, revision)
);
create table public.retro_exports (                      -- 내보내기 감사
  id uuid primary key default gen_random_uuid(),
  day_id uuid not null references public.retro_days on delete cascade,
  revision int not null,
  kind text not null check (kind in ('markdown','notion','link')),
  target_ref text,                                       -- notion page id · slug
  exported_by uuid not null references auth.users,
  created_at timestamptz not null default now()
);
create index retro_days_dept_date on public.retro_days (dept_id, retro_date desc, user_id);
create index retro_days_topics on public.retro_days using gin (topics);
```

**RLS** — 새 개념은 `self` 하나다. `can_see()`는 바꾸지 않는다.

```sql
-- 읽기: 본인이거나, self가 아니면서 can_see()가 허용
create policy retro_days_select on public.retro_days for select to authenticated
  using (user_id = auth.uid()
         or (visibility <> 'self' and can_see(auth.uid(), dept_id, visibility)));
-- 쓰기: 테이블 직접 쓰기 없음. 모든 변경은 SECURITY DEFINER RPC (owner = auth.uid() 재검증)
-- retro_activities · retro_revisions · retro_exports: 부모 day의 select 조건을 exists로 상속
-- anon: 데모 조직만 select (is_demo_department), 쓰기 정책 없음
```

`user_id = auth.uid()`는 가시성 등급 판정이 아니라 **소유 판정**이다. `self`는 `can_see()`에 들어가지 않고, 다른 어떤 테이블도 `self`를 쓰지 않는다. 개인 범위가 두 번째로 필요해지면 그때 PRD §6-12의 예고대로 ACL 테이블로 승격한다(ADR-063).

**RPC** (모두 SECURITY DEFINER, `auth.uid()` 재검증, 데모 조직 거부):

| RPC | 하는 일 |
|---|---|
| `create_retro_day(p_dept, p_day, p_date, p_bundle jsonb)` | 멤버십·동의(`consented_at`) 확인 → 번들 Zod 재검증(크기·종류·`sasu_*` 금지) → `mask_retro_text()` → `retro_activities` upsert(`unique(day_id,kind,ref)`) → **Tier 0 활동을 본인 행에서만 SQL로 추가**(`source_visibility` 기록) → `status='drafting'` → `jobs` insert `id = md5('retro-draft:'||day||':'||revision)::uuid` on conflict do nothing. 같은 날 재업로드는 활동을 합치고 새 초안을 만든다 |
| `save_retro(p_day, p_revision, p_title, p_body, p_topics)` | revision 불일치 → `40001 stale_retro`. 본문 각 항목의 `citations[].activity_id`가 같은 day의 비제외 활동인지, `quote`가 그 활동의 `text`·`title`에 포함되는지 SQL이 검사. 마스킹 재적용. `origin='edit'`로 append |
| `confirm_retro(p_day, p_revision)` | 인용 0개 항목이 있으면 거부. `confirmed_revision`·`confirmed_at`·`topics` 갱신. `origin='confirm'` append. 재확정은 새 revision |
| `set_retro_visibility(p_day, p_visibility)` | `dept`·`leads_only`로 넓히려면 인용된 Tier 0 활동의 `source_visibility`가 모두 그 범위 이상이어야 한다(가장 좁은 것 상속, 불변식 4). 위반 시 `visibility_narrower_source` |
| `exclude_retro_activity(p_day, p_activity, p_excluded)` | 제외 토글. 확정된 revision의 인용은 그대로(재생성해야 반영) |
| `regenerate_retro(p_day)` | `status='drafting'`, revision 기준 새 job id |
| `delete_retro_day(p_day)` | 본인만. cascade 삭제(§0-4) |
| `retro_timeline(p_dept, p_from, p_to, p_user, p_topic)` | 목록. RLS 위에서 `security invoker` — 판정은 정책이 한다 |

job 핸들러가 부르는 서비스 RPC: `claim_retro_draft(p_day, p_revision)`·`finish_retro_draft(p_day, p_revision, p_title, p_body, p_topics, p_error)` — 검토함의 `claim_review_part`/`finish_review_part`와 같은 펜싱.

## 5. 초안 생성 — `retro_draft` job과 인용 검증

- `lib/jobs.ts` `JobKind`에 `retro_draft`, `lib/llm.ts` `LlmPurpose`에 `retro_draft`(생성 모델 `openai/gpt-oss-120b`), 핸들러는 `lib/pipeline/retro-draft.ts`, `lib/worker.ts`에 등록. `sweepPendingRows()`에 `retro_days.drafting` 2분 → `failed/llm_timeout` 추가. 상세 GET은 검토함처럼 읽기 시점에도 2분 방어를 한다.
- 입력: 비제외 활동을 `kind`별로 묶어 `[A-12] 2026-09-19 14:02 git_commit · feat(notion-collection): …` 형태로 나열(활동 500건 × 500자 상한 = 프롬프트 최대 약 25만 자 → **120건 단위 청크 → 부분 초안 → 병합**, 회의 정리 `chunkMeetingItems`/`mergeMeetingSummaries` 패턴).
- 출력 스키마 `RetroDraft` (strict json_schema):

```ts
const RetroCitation = z.strictObject({ activity_id: NonEmptyString, quote: NonEmptyString });
const RetroItem = z.strictObject({ citations: z.array(RetroCitation).min(1), text: NonEmptyString });
export const RetroBody = z.strictObject({
  did:     z.array(RetroItem),   // 한 일
  learned: z.array(RetroItem),   // 배운 것·찾아본 것
  decided: z.array(RetroItem),   // 결정·판단
  next:    z.array(RetroItem),   // 내일·미결
});
export const RetroDraft = z.strictObject({
  citations: z.array(RetroCitation).min(1),   // 근거 우선 작성 유도(카드와 같은 관행)
  title: NonEmptyString,                       // ≤ 60자
  highlight: NullableString,                   // 회사 기여·마케팅용 한 줄. 인용 가능한 사실이 없으면 null
  topics: z.array(NonEmptyString).min(1).max(5),
  body: RetroBody,
});
```

- 검증 `verifyRetroDraft(draft, activities)` (`lib/retro/verify.ts`, TDD): 각 항목의 `citations`에서 `activity_id`가 존재하고 제외되지 않았으며 `quote`가 `activity.text` 또는 `activity.title`에 **문자열로 포함**되는 것만 남긴다. 인용이 0개가 된 항목은 버린다. 남은 항목이 0개면 `status='needs_review'`(초안 없음, 활동만 보여 준다). `highlight`는 본문 항목 중 하나의 인용을 공유해야 하며 아니면 null. 카드의 `verifyCitations`와 같은 한 줄 규칙이다.
- 저장: `finish_retro_draft` → `retro_revisions(origin='draft')` → `status='draft'`.
- 알림: `members.slack_user_id`가 있으면 `openDirectMessage`+`postMessage`로 "9월 19일 회고 초안이 준비됐어요 · 활동 37건 · [열기]". 실패해도 초안은 남는다(`send_slack` 잡의 에러 코드 재사용).
- 프롬프트 규칙: 1인칭 평서문, 활동에 없는 사실 금지, 회사 이름·고객명 추측 금지, `web_visit`는 "찾아본 것"으로만 쓰고 방문 이유를 지어내지 않는다. `highlight`는 외부 공개를 전제로 내부 코드명·미공개 일정을 넣지 않는다.

## 9. 보안·불변식 점검

| 불변식 | 회고에서 지키는 방법 |
|---|---|
| 1 가시성은 `can_see()` 하나 | `self`는 소유 판정(`user_id = auth.uid()`)이고 `can_see()`에 들어가지 않는다. `dept`/`leads_only`는 그대로 `can_see()` |
| 2 사용자 경로 service role 금지 | 업로드·목록·상세·확정은 세션 클라이언트 + RPC. service role은 `retro_draft` 잡과 데모 시드만. 2단계 토큰 업로드는 **수집 어댑터**로 분류하고 `create_retro_day_as(p_user,…)`에 `auth.role()='service_role'` 가드(`search_as` 패턴) |
| 3 `dept_id`·행위자는 세션에서 | `user_id`는 항상 `auth.uid()`. 번들의 어떤 필드도 사람·부서를 지정하지 못한다 |
| 4 파생물은 가장 좁은 원본 상속 | `set_retro_visibility`가 인용된 Tier 0 활동의 `source_visibility`보다 넓게 열지 못한다 |
| 5 인용 없으면 렌더 없음 | `verifyRetroDraft` + `save_retro`/`confirm_retro`의 SQL 재검증 + UI 필터 3중 |
| 6 미동의 멤버 발언 저장 금지 | 회고는 본인 활동만 담는다. Tier 1·2에 타인 발언이 섞일 수 있는 경로(assistant 응답·붙여넣은 본문·도구 결과)는 **파서가 아예 읽지 않는다**. 업로드는 본인 `consented_at`이 있어야 한다 |
| 9 로그에 원문 금지 | day id·활동 건수·에러 코드만. 수집기도 `--dry-run` 외에는 제목을 stdout에 찍지 않는다 |
| 마스킹 | 수집기 `mask()` + SQL `mask_retro_text()`. 마스킹 전 저장 없음 |
| 12 데모 | `orgs.is_demo`면 RPC가 거부. `/demo/retros`는 시드 읽기만 |
| 22 운영 반영 | 하니스·E2E·리뷰 뒤 사용자 승인. 9/20 이후 |

추가 규칙(§6-4로 ARCHITECTURE에 올린다):

- **회고 활동은 본인 것만, 짧게, 마스킹 후.** 응답·도구 결과·붙여넣기·diff 본문·URL 쿼리는 수집 대상이 아니다. 활동 1건은 500자를 넘지 않는다.
- **회고 삭제는 본인만 가능하고 하루치 전체다.** revision은 append-only이며 부분 삭제는 없다.
- **공개 링크는 조직 관리자 승인 + `dept` 회고 + 브라우저 활동 미포함**일 때만 만들어진다.
- 개인 토큰(2단계)은 sha256 해시만 저장, 스코프 `retro:upload` 하나, 90일 만료, 본인 폐기, 분당 1번들·1MB.

## 12. 개통 전에 확인할 것

- Chrome History 복사본을 읽는 데 Node `node:sqlite`(22.5+ 실험 플래그) 또는 `better-sqlite3` 중 무엇을 쓸지 `(확인 필요: 현재 Node 버전·네이티브 빌드 가능 여부)`. 안 되면 Python `sqlite3`로 우회하는 보조 스크립트를 둔다(`py -3`).
- 노션 내부 통합 토큰의 "콘텐츠 삽입" capability와 부모 페이지 공유 여부 `(확인 필요: 2단계)`.
- Groq 120b가 활동 120건 청크에서 인용 quote를 원문 그대로 옮기는 비율 — 카드에서 쌓인 `citation_invalid` 비율과 비교해 청크 크기를 정한다.
- 여러 부서 소속 사용자의 회고 중복(§0-6) — 첫 파일럿에서 실제 불편이 있는지 본다.
- Claude Code 세션 파일 형식(`ai-title`·`promptSource`)은 CLI 버전(2.1.276에서 확인)에 따라 바뀔 수 있다 — 파서는 알 수 없는 레코드를 무시하고 `collector.version`을 남긴다.
