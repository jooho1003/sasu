# Slack 기록 문서화·보존·백업 운영안

- 작성/공식 문서 확인: **2026-09-16**
- 상태: **수집 현황·MD/체크섬 JSON 내보내기·암호화 격리 복원 도구 개발. 운영 자동 백업·장기 보존 정책은 미확정**
- 상위 범위: [PRD §3-3 IN-03·§8·§10 #27](../PRD.md), [ADR-053](../ADR.md)
- 목적: Slack 요금제·보존 기한으로 업무 근거가 사라지기 전에, 허용된 부서 기록을 문서화하고 실제 복원 가능한 상태로 보관한다.

## 1. 먼저 구분할 사실

| 항목 | 공식 문서에서 확인한 내용 | 사수의 설계에 미치는 영향 |
|---|---|---|
| 무료 플랜 열람 | 최근 90일의 메시지·파일 기록에 접근할 수 있다 | 90일 전에 접근 가능했던 자료가 계속 API로 조회된다고 가정하지 않음. [공식 제한 안내](https://slack.com/help/articles/27204752526611-Feature-limitations-on-the-free-version-of-Slack) |
| 보존과 삭제 | 무료 플랜은 90일 또는 1년 보존을 선택할 수 있고, 보존 정책으로 삭제된 데이터는 영구 삭제다 | **90일 열람 제한과 삭제일은 별개**. 실제 설정을 확인해 더 이른 위험 시점을 기준으로 준비. [보존 정책](https://slack.com/help/articles/203457187-Customize-data-retention-in-Slack) |
| 업그레이드 | 90일 제한으로 숨겨진 기록은 업그레이드 시 다시 보일 수 있지만, 이미 삭제된 기록은 대상이 아니다 | 나중에 결제하면 모든 과거 자료를 복구할 수 있다고 안내하지 않음. [제한 안내](https://slack.com/help/articles/27204752526611-Feature-limitations-on-the-free-version-of-Slack), [가져오기/내보내기 안내](https://slack.com/help/articles/204897248-Guide-to-Slack-import-and-export-tools) |
| 무료 플랜 일반 내보내기 | 공개 채널 메시지와 파일 링크를 JSON으로 내보내는 경로가 있다. 파일 링크는 최근 90일 제한이 있다 | 공개 채널 export를 비공개 채널·DM 전체 백업으로 설명하지 않음. 추가 export 자격·승인은 따로 확인. [내보내기 절차](https://slack.com/help/articles/201658943-Export-your-workspace-data) |
| 첨부 파일 | 일반 export는 파일 실물 대신 링크를 포함한다 | ZIP이 있어도 첨부 파일 복원이 보장되지 않음. 승인된 실물 다운로드와 검증을 별도 계획. [도구 안내](https://slack.com/help/articles/204897248-Guide-to-Slack-import-and-export-tools) |
| API 접근 | 봇의 history 조회는 scope 및 참여한 conversation 범위에 제한된다. `is_limited`는 무료 한도 때문에 이전 자료가 제한됐음을 나타낼 수 있다 | 앱 설치만으로 워크스페이스 전체가 수집되지 않음. 제한 신호·권한·실제 응답을 수집 범위 보고서에 반영. [history API](https://docs.slack.dev/reference/methods/conversations.history/) |
| API 속도 | Marketplace/내부 고객 제작 앱과 신규 비Marketplace 상용 배포 앱의 history/replies 제한은 다르다. 후자는 분당 1회·페이지 최대 15건 제한이 명시돼 있다 | 고객사 설치 모델에서 기존 분당 50회 가정을 사용하지 않음. 설치 유형·응답·Retry-After로 계획. [history API](https://docs.slack.dev/reference/methods/conversations.history/), [rate limits](https://docs.slack.dev/apis/web-api/rate-limits) |

이 표는 Slack 일반 정책 확인이다. **현재 운영 워크스페이스의 실제 요금제·체험/유료 종료일·보존 설정·내보내기 권한은 이번 문서화에서 조회하지 않았다.** 실제 보존 실행 전 다시 확인하고 확인자·시각을 기록한다. 요금제 변경이나 유료 전환을 실행하지 않는다.

## 2. 현재 사수가 하고 있는 것과 아닌 것

- 동의한 멤버의 연결된 채널 메시지를 수신해 마스킹한 텍스트를 사수 DB에 저장한다. 원문 편집·삭제 동기화와 버전 처리는 phase 16에 있다.
- 현재 백필 구현은 **최근 7일**을 기준으로 `conversations.history`를 페이지 처리한다. 이는 90일 전체·모든 스레드·모든 첨부를 보관하는 작업이 아니다. [현재 구현](../../lib/pipeline/slack-backfill.ts)
- OAuth 워크스페이스 설치는 수집 허용 범위를 넓혀주는 보존 승인이 아니다. 부서 채널·멤버 동의·공개 범위 설정이 따로 필요하다.
- 9/16 배포 전 DB schema/data dump는 일회성 롤아웃 백업이다. Slack 첨부·원본 음성·정기 백업·복원 훈련 완료를 의미하지 않는다. [운영 기록](../verification/continuity-production-2026-09-16.md)
- 업무 내용의 정기 문서화, 장기 보존용 export, 외부 백업 저장소, 주기적 복원 점검은 이번에 요구로 등록한다.

## 3. 서로 다른 세 산출물

| 산출물 | 담는 것 | 용도 | 이것만으로 해결되지 않는 것 |
|---|---|---|---|
| 부서 업무 정리 문서 | 주제·기간별 사실, 결정, 담당자, 할 일, 열린 질문, 인용 | 사람이 읽고 에이전트가 참고하는 업무 기억 | 요약에서 빠진 원문·첨부 복구 |
| 권한을 유지한 기록 아카이브 | 허용된 원문 텍스트·메타데이터·버전·출처, 승인된 첨부 실물, manifest | Slack 접근 만료 후의 승인된 기록 보존 | DB 전체 복원·사용자/권한/설치 설정 복구 |
| 시스템 복구 백업 | DB schema/data, 필요한 객체 저장소, 복구에 필요한 설정 참조 | 장애·손상 시 서비스 복구 | 읽기용 지식 문서, 모든 Slack 과거 자료의 완전성 |

사용자가 요구한 “미리 문서화하고 백업”에는 세 가지가 모두 관계된다. 문서 요약 성공과 백업/복원 성공을 별도로 판정한다. 암호화 키·Slack 토큰을 일반 문서나 다운로드 묶음에 넣지 않는다.

## 4. 최초 보존 준비 절차 (실행 전 체크할 운영안)

| 순서 | 확인/작업 | 남길 증거 |
|---|---|---|
| 1 | 워크스페이스별 요금제·변경 예정일·보존 설정·Slack export 권한 확인 | 확인 일시·담당자·설정 근거. 실제 값을 모르면 `확인 필요` |
| 2 | 부서별 대상 채널·기간·멤버 동의·공개 범위·첨부 포함 범위 확정 | 승인된 대상 목록. 같은 조직이어도 다른 부서 자료를 합치지 않음 |
| 3 | 기존 사수 수집 범위 조회 | 채널별 가장 이른/늦은 수집 시각·최근 성공·누락 구간·제한 신호. 권한 있는 대상만 표시 |
| 4 | 현재 접근 가능한 과거 기록 보충 계획 | API/공식 export 중 가능한 방법, 예상 호출량·시간, 봇 권한·스레드/첨부 누락 여부 |
| 5 | 권한·동의 필터와 마스킹 후 기록 반영 | 작업 ID·수집 건수·기간·실패/누락 사유. 원시 export를 앱의 공개 폴더/리포/로그에 저장하지 않음 |
| 6 | 업무 정리 초안 작성 및 검토 | 인용·출처가 있는 정리 문서와 확인 기록. “논의”를 “결정”으로 바꾸지 않음 |
| 7 | 기록/첨부/manifest 보관 및 별도 복구 백업 | 보관 위치 참조·체크섬·실물 포함 여부·정책 버전·최종 성공 시각 |
| 8 | 격리 환경으로 복원 시험 | 건수/체크섬/연결/인용/권한/삭제 재적용 확인 결과. 실운영 Slack 전송·LLM job 재실행은 차단 |

공식 export 파일에 대상 밖 채널이나 미동의 발언이 포함될 수 있다. 전체 ZIP을 사수 DB·운영 백업에 무조건 적재하는 방식은 채택하지 않는다. 원시 export의 수령·필터·임시 취급·파기는 별도 승인 범위를 정한 뒤 구현하며, 기존 미동의 원문 비저장 원칙을 유지한다.

## 5. 정기 운영 제안 — 아직 합의할 값

| 운영 항목 | 초기 제안 | 확정할 것 |
|---|---|---|
| 신규 기록 확보 | 기존 이벤트 수집 + 매일 수집 누락 대조 | 채널 규모·스레드 보충 범위·API 호출 예산 |
| 정리 문서 | 주간 업무/결정/열린 질문 초안, 부서 담당자 검토 후 발행 | 주제 분류·주기·확인자·발행 위치 |
| 보존 위험 안내 | 플랜 만료 및 가장 오래된 미보관 자료 기준 사전 안내 | 알림 담당자·예고 기간·보관 완료 판단 |
| 복구 백업 | 매일 1회 검증된 암호화 백업을 별도 위치에 보관하는 안 | 저장소·비용·암호화 키 관리·백업 보관 기간 |
| 복원 시험 | 최초 1회, 이후 월 1회 및 주요 schema 변경 후 | 복구 허용 시간·허용 데이터 손실량·검증자 |
| 실패 대응 | 성공 시각이 갱신되지 않으면 담당자에게 상태/재시도 안내 | 지연 허용치·알림 경로·재시도 횟수 |

매일 1회 제안도 24시간 데이터 손실을 보장한다는 뜻은 아니다. 수집 지연·실패와 실제 복원 시간을 측정해 복구 목표를 정한다. 보관 기간은 “무기한”으로 기본값을 두지 않고 업무 기록·원장·첨부·음성·복구 백업 각각 정한다.

UI에는 권한 있는 채널에 한해 **수집된 기간 / 확인하지 못한 구간 / 마지막 백업 성공 / 마지막 복원 시험 / 첨부 실물 포함 여부**를 보여준다. API 결과가 일부이거나 실패한 동안에도 `완료`로 표시하지 않는다. 조직 관리자는 메타데이터를 볼 수 있어도 백업 버튼 하나로 부서 내용을 다운로드할 수는 없다.

## 6. 삭제 동기화와 보존 정책의 충돌

현재 정책(ADR-022·052)은 원문 삭제 시 `items.content`·임베딩을 비우고 기존 결정의 인용 스냅샷만 보존한다. 따라서 현재 동기화 테이블만으로 **Slack에서 지워져도 모든 원문이 영구히 남는다**고 말할 수 없다.

| 상황 | 유지할 처리 / 설계 시 결정할 점 |
|---|---|
| 무료 열람 제한 또는 API 권한 상실 | 조회되지 않았다는 사실만으로 원문 삭제로 단정하지 않음. 자료의 현재 유효성/동의/사수 보존 정책은 별도 검증 |
| 실제 편집·삭제 이벤트 | 현재 버전 갱신·본문 제거·파생물 무효화 정책 유지. 누가 왜 삭제했는지 정보가 없으면 사유를 추정하지 않음 |
| “업무 기록으로 별도 보존” 모드 | 수집 동의 범위·별도 기록의 보존 목적/기간·조회자·삭제 요청·Slack 삭제 반영 관계를 사용자와 먼저 합의. 결정 전 활성화하지 않음 |
| 결정 인용 스냅샷 | 기존 append-only 근거 보존을 유지하되, 원문 삭제/변경 사실과 현재 인용 유효성은 명확히 표시 |
| 백업에 삭제 전 사본이 남음 | 접근 제한·보관 만료·파기 절차를 정하고, 복원 시 최신 삭제 목록과 권한 변경을 재적용해 삭제 자료를 되살리지 않음 |

Slack 원문 링크가 더 이상 열리지 않더라도, 적법하게 보관하기로 합의된 사수 기록이 있으면 **현재 권한 안의 보관본**을 출처로 안내하는 기능이 필요하다. 원래 Slack 링크와 보관본을 구분하고, 보관 시각·버전·현재 상태를 표시한다. 이는 후속 요구이며 현재 모든 링크가 대체됐다는 뜻이 아니다.

## 7. 보관 묶음과 복원 요구사항

초기 구현은 하나의 JSON에 `manifest`, `records`, 원문 기반 `markdown`을 포함한다. 별도 MD 다운로드도 지원한다. 체크섬은 records의 JSONL 직렬화와 markdown에 각각 적용한다. AI 주간 요약이나 Slack 첨부 실물 보관은 포함하지 않는다. 아래 세부 항목은 확장 시 고려할 요구다.

- manifest: 조직/부서/소스 식별자, 기간, 생성 시각, 생성 도구/schema 버전, 건수, 파일별 체크섬, 완료/부분 상태, 수집 누락 사유, 첨부 포함 여부, 보관 정책 버전. 비밀값 없음.
- records: workspace/channel/message/thread 식별자, 원문 시각·수집 시각, 마스킹된 텍스트, 버전, 작성자 매핑, 동의 근거 참조, 공개 범위, 편집/삭제 상태. 중복 합치기 기준은 출처 식별자와 버전이다.
- summary: 출처/버전 인용, 사실·미결 사항·결정의 구분, 검토자/시각. 요약이 원문을 대신하지 않음.
- attachments: 실제 파일과 체크섬·원래 파일 식별자·접근 범위. 링크만 있으면 `실물 미포함`으로 기록.
- 복구 백업은 공개 링크로 노출하지 않고 별도의 운영 권한으로 보호한다. 암호화 키는 백업 본문과 별도로 복구 가능하게 관리하되 키 자체를 로그·리포·문서에 적지 않는다.
- 복원은 schema → 데이터/객체 → 관계/체크섬 → 최신 권한/동의/삭제 상태 재적용 → 검색 재생성 → 인용 검증 순서의 초안이다. 상세 순서는 DB FK·확장·암호화 의존성 확인 후 확정한다.
- 복원 중 jobs/cron/Slack 발송은 정지 상태로 두고 자동 재발송을 막는다. 검증 후 필요한 job만 명시적으로 재개한다.

## 8. 완료 판정 및 미결정

완료 증거는 “ZIP 다운로드 성공”이 아니라 다음 항목이다.

1. 한 개의 승인된 부서/채널에서 수집 기간·공백·스레드·첨부 범위를 보고할 수 있다.
2. 확인된 텍스트/정리 문서와 원문 버전·인용이 연결된다.
3. Slack 링크를 열 수 없는 합성 상황에서 권한 있는 보관본을 확인할 수 있다.
4. 백업에서 격리 복원한 데이터/파일의 건수·체크섬·인용 관계가 일치한다.
5. 다른 부서 사용자와 권한 회수자는 자료를 볼 수 없고, 삭제 자료가 복원으로 부활하지 않는다.
6. rate limit·부분 export·첨부 다운로드 실패·키 유실·보관 만료가 실패/부분 완료로 표시된다.

실제 플랜/만료일·기간·정기 보관소/비용/기간·복원 목표·담당자는 운영 적용 전에 정한다. 로컬 합성 채널의 내보내기와 암호화 백업/격리 DB·파일 바이트 복원, 최신 삭제·동의 재적용을 실행했다. [검증 기록](../verification/reviewed-materials-2026-09-16/README.md)과 [도구 제약 및 운영 절차](../setup-reviewed-materials.md)를 참조한다. 실제 Slack 전체 export·운영 정기 백업·서비스 복구 완료 기록은 아니다.
