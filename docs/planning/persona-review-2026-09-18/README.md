# 사수 부서·직급별 사용성 검토와 개선 설계

작성: 2026-09-18. 사용자 요청: 두 시간 범위의 심층 검토, **소규모와 중견 규모를 함께 비교**, 다른 세션이 개발 중이므로 검토 중심으로 진행.

이 문서는 검토 결과와 **제안 설계**다. 확정 범위는 [PRD](../../PRD.md)가 우선하며 이 문서가 PRD·ADR·phase 완료 상태를 바꾸지 않는다. 실제 인터뷰를 진행한 결과가 아니라 현재 코드·명세와 합성 업무 사례로 만든 **가설 페르소나**다. 사람의 나이·성별 대신 업무 책임, 결정 권한, 정보 접근, 실패 비용을 기준으로 구분했다.

## 핵심 판단

사수의 강점은 이미 결정한 이유를 다시 찾고, 미결 안건을 놓치지 않으며, 권한 안에서 근거를 확인하는 흐름이다. 소규모에서는 대표·팀장의 반복 설명과 기억 부담을 줄일 가능성이 크다. 중견 규모에서는 부서 안의 결정 기록에 먼저 적용할 수 있지만, 여러 결재 단계·겸직·부서 간 협의를 현재 `member/lead`만으로 표현하기 어렵다. **회사 규모가 커졌다고 관리자에게 모든 내용을 보이게 하는 접근은 현재 설계와 맞지 않는다.**

검토에서 우선 드러난 항목은 다음과 같다.

1. **사람이 결정 결과를 편집해야 한다(G01).** 실제 웹 컴포넌트에 ‘5%만 승인’ 사유를 입력해도 요청 `outcome`에는 AI 추천인 ‘12% 승인’이 남는 것을 재현했다. Slack 모달에는 결과 편집란이 있다. 개선은 [D01](designs.md#d01-사람이-확정하는-결정-내용).
2. **근거 부족에서 사람에게 인계하는 길이 필요하다(G02).** 묻기는 카드 승격 안내를 하지만 해당 결과 화면의 행동은 ‘이어서 질문하기’뿐이다. 담당자에게 확인을 요청하는 별도 절차가 필요하다. [D02](designs.md#d02-답변에서-사람에게-확인-요청).
3. **업무 담당자·최종 결정자·열람 권한은 서로 다르다(G03).** 현재 이름 일치/첫 lead로 지정한 카드 담당자가 결정할 수 있다. 직급이나 AI가 추정한 이름이 회사의 승인 규칙을 대신해서는 안 된다. [D03](designs.md#d03-결정-책임과-기간-한정-대행).
4. **입력·검토 업무가 lead에 몰린다(G04).** 자료 검토와 문서 역할 실행 권한을 얻기 위해 실무자를 모두 lead로 승격하면 비공개 열람·결정 권한까지 넓어진다. 초안 기여와 확정을 나눠야 한다. [D04](designs.md#d04-자료-기여와-검토-분리).
5. **중견 도입은 ‘회사 전체 검색’보다 권한이 명확한 부서 파일럿부터다(G07·G14).** 공용 정책과 민감한 HR 사례, 부서 간 전달문은 서로 다른 공개 계약이 필요하다. [D07](designs.md#d07-부서-간-통제된-전달).

## 검토의 경계

- 이 작업에서는 제품 코드·DB·배포·공용 phase 파일을 변경하지 않았다. 실행용 검토 파일과 이 문서 묶음만 추가했다. 이전 Notion 독립 검토 작업의 변경은 [별도 보고서](../../verification/notion-collection/step2-independent-review.md)에 있다.
- 실사용자에게 메시지·이메일을 보내거나, 실제 고객 자료를 넣거나, LLM 유료 호출을 하지 않았다. 브라우저 재현의 `/api` 요청은 모두 합성 응답으로 차단·대체했다.
- 실제 고객 인터뷰, 운영 환경 재검증, 부하·보안 인증을 했다고 주장하지 않는다. 기존 운영 검증 기록은 작성 주체와 날짜가 다른 증거다.
- PRD 타깃은 **5~50인 팀**이다. 아래 조직 전체 규모 비교는 사용자가 요청한 검토 시나리오이며 타깃 변경 결정이 아니다. ‘중견’은 여기서 조직 구조를 설명하는 말이며 법적 기업 분류가 아니다.
- 동시에 바뀌는 작업 트리를 검토했다. 주요 입력 파일의 해시와 확인 시각은 [검증 폴더](../../verification/persona-review-2026-09-18/)에 기록한다. 수정 반영 전 해당 파일을 다시 확인해야 한다.

## 구현으로 옮길 때

기존 명세를 충족시키는 G01·G02부터 담당 개발 세션에 전달하고, 새 범위를 만드는 설계는 PRD §3·§8 반영 → ADR → phase step으로 승격한다. 업무별 실제 사례와 권한 계약은 사용자와 공동 설계한다. [부서 에이전트 공동설계 원칙](../부서_에이전트_공동설계.md)을 따른다. 여기서 제안한 외부 시스템 실행·조직 전체 검색·인사평가 권한은 없다.
