# 운영·IT·보안·구매 운영: 예외와 인계의 정확성

운영군의 실제 소유자는 조직마다 다르다. IT 접근 관리·서비스 운영·구매/납기 조정은 각각 다른 정책을 적용한다. 사수의 연결 관리자는 곧 보안 조사관이 아니며, 운영 매뉴얼 Q&A는 실제 시스템 상태 확인이 아니다.

| 페르소나·상황 | 실제 이용 방식 | 장점 가설 | 단점·실패 조건 | S/M 차이·검증 질문 |
|---|---|---|---|---|
| **OP-L1 운영 신입·헬프데스크**. 반복 절차와 담당자 확인 | 공용 runbook/절차 ASK → 인용 열기 → 현재 티켓/상태 확인 | 야간·선임 부재 시 기본 절차 탐색 | 오래된 절차를 실행하거나 비밀정보를 질문에 넣음(G06·G09·G21) | S는 비전문 겸직. M은 교대·권한 분리. **절차와 실제 상태를 따로 확인하는가?** |
| **OP-L2 운영 담당자**. 납기/장애/계정 예외 처리 | 내부 논의를 카드로 만들고 결정 기록 → 실제 ERP/IT도구에서 별도 실행 | 인계 시 왜 예외를 허용했는지 남음 | 실행권한/최신 재고/계정 상태 연동 없음, 작업 완료 오해(G15·G16) | S는 요청·실행 같은 사람. M은 구매/물류/IT 별도 대기열. **실행되지 않은 결정이 남아 있음을 아는가?** |
| **OP-L3 선임·보안/품질 전문가**. 변경 위험 자문 | 자료의 확인 가능한 근거로 검토 의견, 운영 메타데이터는 org admin 범위에서 확인 | 근거·조건·검토 책임을 분명히 할 가능성 | 문서 실행 권한 때문에 lead 부여하면 불필요한 본문 접근. 익명화로도 사건 식별 가능(G04·G20·G27) | S는 외부 자문 가능. M은 보안 검토와 운영 권한 분리. **‘안전’ 점수가 실제 검증 완료처럼 보이지 않는가?** |
| **OP-L4 운영 팀장·책임자**. 교대·장애·납기 우선순위 | 미결·보류 카드 확인 → 우선 처리·대행 지정은 현재 수동 협의 → 원장 인계 | 누락된 판단을 회고·교대 시 찾음 | 대행/재배정 화면 부족, 여러 원본에서 같은 이슈 알림 중복(G03·G24·G28) | S는 한 명에게 집중. M은 교대 종료 시 책임 자동 해제 필요. **다음 교대가 처리할 미결만 정확히 받는가?** |
| **OP-L5 COO·운영 본부장**. 여러 부서의 장애·납기·보안 상충 | 공유 승인된 최소 요약으로 자원/위험 선택, 운영 admin은 연결/보존 문제 해결 | 조직 간 결정 대기의 원인을 볼 가능성 | 현재 실시간 전사 상황판 없음. 원문/질문까지 감시하려 하면 도입 신뢰 저하(G07·G20·G27) | S는 설정까지 직접 담당. M은 운영 책임자와 개인정보 책임 분리. **메타데이터만으로 해결 가능한 문제를 구별하는가?** |

[J09 교대·휴가 인계](../journeys.md), [J12 동의/권한 변경](../journeys.md)을 우선 검증한다. 장애 자동 복구·ERP 주문·계정 생성 같은 외부 실행은 이번 설계가 부여하는 권한이 아니다.
