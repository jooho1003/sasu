# 10부서군 × 5책임 단계의 가설 페르소나

50개는 사용 상황의 수이며 서로 다른 실제 사람 50명을 조사했다는 뜻이 아니다. S는 전체5~50명, M은 전체100~500명 안의 부서5~50명이라는 [비교 가정](../scope-and-size.md)이다. L1~L5는 직함을 권한으로 자동 변환하지 않는 책임 단계다. 모든 사례·금액·고객명·프로젝트는 합성이다.

현재 부서·채용 데모와 가까운 다섯 군을 먼저 보고, 영업·마케팅·CS·경영지원·운영으로 확장했다. 일반 개발 부서의 역할은 FE/BE 두 군에 포함했다. 재무·법무, 운영·IT·보안은 회사마다 다른 부서이므로 묶음 안의 업무도 별도 소유자를 유지한다.

| ID 접두어 | 부서군 | 자주 필요한 판단 | 먼저 검증할 가치 | 특히 큰 제약 |

각 행은 실제 경로로 가능한 행동과 부족한 기능을 함께 적었다. 빈도가 ‘매일/주간’인 것은 모집 시 확인할 가정이며 현재 사용량 통계가 아니다. 개선 번호 Gxx는 [별도 부족 기록](../gaps.md)에 연결된다. 묶음별 장점은 잠재 가치이며 측정된 효과가 아니다.

## 여러 부서에서 같은 단어가 다른 뜻을 가진다

- ‘승인’: 디자인 피드백 확정, 출시 허용, 할인 권한, 구매 전결은 서로 다른 권한이다. `decided` 하나로 회사의 모든 승인 절차를 완료했다고 표현하지 않는다.
- ‘담당’: 자료 작성자, 검토자, 카드 수신자, 결정자, 후속 실행자를 구별한다.
- ‘정책’: 참고 원칙, 한 고객 예외, 기간 한정 실험, 현재 시행 규정을 구별한다.
- ‘완료’: 결정 완료와 실제 배포·입금·고객 안내·문서 반영 완료를 구별한다.

## 직급에 공통인 마찰

L1은 답변을 얼마나 믿어도 되는지와 사람에게 물어볼 길이 필요하다. L2는 자기 업무 흐름에서 적은 조작으로 근거를 찾고 기록하고 싶다. L3는 실무 기여·검토 권한과 최종 책임을 분리할 필요가 있다. L4는 자신에게만 쌓이는 알림·자료 확인 부담을 줄여야 한다. L5는 과도한 원문 열람 없이 부서 간 선택과 위험을 이해하고 싶다. 조직·개인마다 달라 실제 인터뷰에서 반증해야 한다.
