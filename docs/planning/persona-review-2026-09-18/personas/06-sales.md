# 영업·사업개발: 고객에게 약속하기 전 확인

입력은 가격/할인 원칙·동의된 내부 딜 리뷰·정해진 범위의 고객별 결정이다. CRM 자동 갱신, 견적 발송, 계약 체결, 고객 통지는 현재 사수가 실행하지 않는다. 가격·마진 같은 정보는 공개 범위를 먼저 정한다.

| 페르소나·상황 | 실제 이용 방식 | 장점 가설 | 단점·실패 조건 | S/M 차이·검증 질문 |
|---|---|---|---|---|
| **SA-L1 신입 영업**. 가격·납기 답변을 매일 준비 | 모바일/Slack DM에서 기준 질문 → 인용/날짜 확인 → 예외는 담당자에게 확인 | 고객 앞에서 근거 없는 약속을 줄일 가능성 | ‘지난 고객의 승인’을 모든 고객에게 적용, 근거 부족 인계 없음(G02·G06·G08) | S는 대표에게 묻기 어려운 시간대. M은 상품/지역별 규칙. **예외 답변을 표준 정책으로 오해하지 않는가?** |
| **SA-L2 계정 담당 AE**. 특정 고객 할인·납기 조정 | Slack 논의를 카드로 만들고 조건/근거 확인, 승인 뒤 CRM·견적에 별도 반영 | 협상 과정의 변경 이유와 내부 확인을 남김 | AI 담당자 지정으로 사실상 승인자가 되거나 직접 기록을 회사 승인처럼 표현(G03·G19) | S는 가격재량 넓을 수 있음. M은 금액별 전결·재무 동의 필요. **본인이 처리 가능한 정확한 범위를 아는가?** |
| **SA-L3 선임·딜 지원 담당**. 복잡한 조건 검토 | 과거 동일 고객·상품 결정과 원칙을 대조, 위험 조항을 문서 역할로 보조 점검 | 후배의 재확인을 도우며 논거를 통일 | 비슷한 계약의 문구가 다른 조건에 잘못 적용. 문서 점수는 계약 검토 완료 아님(G08·G10·G15) | S는 실무 코치. M은 영업/법무/재무를 연결하는 전문가. **적용할 수 없는 선례를 설명하는가?** |
| **SA-L4 영업 팀장**. 가격 예외 최종 확인 | 카드에서 추천 검토→결정 기록→알림/원장, 필요시 정정 | 출장 중에도 근거를 확인해 결정 이유 공유 | 웹은 결과 편집이 없어 다른 조건 승인 의도를 잘못 기록할 수 있음. 고객/기한별 큐 부족(G01·G05·G25) | S는 대표 결재와 겸함. M은 자신의 한도 밖 추가 승인 필요. **12% 요청을 5%로 수정해 확정할 수 있는가?** |
| **SA-L5 영업 본부장·대표**. 전략 고객과 수익성 상충 | 부서가 공개한 딜 판단 요약/예외 추세 확인 → 책임 범위 선택 | 예외가 정책이 된 과정을 발견할 가능성 | 현재 매출/CRM 연동 통계 없음, 개별 상담 원문을 전사로 확대할 위험(G07·G16·G20) | S는 직접 고객 담당. M은 재무/제품과 약속 범위를 합의. **전략 선택과 고객에게 전달된 조건이 일치하는가?** |

[J02 할인 예외](../journeys.md)는 이번 컴포넌트 실행에서 실제로 재현한 문제와 연결된다. 고객 사례는 전부 합성이다. 순효과는 확인 소요 시간뿐 아니라 잘못된 약속·정정·재견적 비용을 함께 본다.
