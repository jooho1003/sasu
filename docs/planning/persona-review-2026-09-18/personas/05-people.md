# 인사·채용·조직 운영: 공용 정책과 개인 사례를 분리

공용 복무/온보딩 정책과 개인 보상·고충·조사·건강 정보는 같은 입력 범주가 아니다. 현재 `leads_only`는 해당 부서의 모든 lead에게 보일 수 있으므로 개별 사건 담당자만 알아야 하는 사례에는 충분하지 않다. 이번 제안은 직원 인사평가·자동 채용 판정을 추가하지 않는다. 채용 개별 링크는 PRD1.14/phase26 설계와 조율하며 구현 완료로 취급하지 않는다.

| 페르소나·상황 | 실제 이용 방식 | 장점 가설 | 단점·실패 조건 | S/M 차이·검증 질문 |
|---|---|---|---|---|
| **HR-L1 인사 운영 신입**. 온보딩 준비·기본 규정 확인 | 승인된 공용 정책을 ASK → 시행 시점/대상 확인 → 필요한 담당자에게 인계 | 규정 검색과 반복 질문 감소 | 다른 부서 직원에게도 같은 자료가 보이는지 착각. 과거 규정을 현재 규정으로 안내(G06·G07·G21) | S는 대표 구두 관행 의존. M은 고용형태·지역별 차이가 큼. **적용 대상이 다른 경우 답변을 멈추는가?** |
| **HR-L2 채용·온보딩 담당자**. 일정·역할·서류 준비 | 회의 확정 자료로 일정 결정 기록, 채용 예고편은 합성 데모/승인된 범위만 사용 | 면접관과 입사 준비 담당자의 누락을 추적 | 외부 지원자 자료의 목적·동의·보존 경계, 문서 점수의 합격 판정 오해(G11·G18·G26) | S는 채용/입사 준비 한 명. M은 recruiter/HR ops/현업 면접관 분리. **지원자가 실제 제출하는 흐름과 데모를 구별하는가?** |
| **HR-L3 HRBP·정책 전문가**. 예외 해석·현업 상담 | 공용 규정 근거를 확인하고 비식별화된 일반 해석만 공유, 민감 사건은 기존 제한 시스템 유지 | 일관된 안내와 예외 발생 이유를 기록 | 비식별화만으로 재식별이 없어지지 않음. 부서 lead 전체 공개가 과도(G07·G20·G26) | S는 겸직으로 권한 경계가 흐림. M은 보상/노무/채용별 접근이 다름. **누가 보면 안 되는지 구체적으로 말할 수 있는가?** |
| **HR-L4 인사 팀장**. 정책 변경·온보딩 기준 승인 | 근거가 있는 정책 변경 카드와 적용 시점을 확정, 후속 공지 별도 관리 | 결정 근거와 변경 이력을 다음 담당자에게 인계 | 역할 이름만으로 법적/조직 승인 완료 오해, 자동 배정이 최종 책임과 다름(G03·G06·G19) | S는 대표 최종 승인 별도. M은 노무·법무·재무 협의 필요. **사수 기록과 공식 정책 발효가 구별되는가?** |
| **HR-L5 CHRO·대표**. 조직 정책과 채용 경험 점검 | 공용 정책의 미결·개선 요청을 집계 수준으로 확인, 개인 질문 원문을 요구하지 않음 | 조직 안내의 빈틈과 반복되는 제도 혼란을 발견할 가능성 | 질문 수/속도를 직원 성과·불만 감시로 활용하면 신뢰 저하(G20·G27) | S는 구성원 식별이 쉬워 집계도 조심. M은 운영/열람 책임 분리. **직원에게 수집 목적과 보지 않는 정보를 설명하는가?** |

우선 도입 후보는 **일반 온보딩 규정**이다. 개인 보상·징계·고충·면접 원본 비교는 현재 파일럿에서 제외한다는 연구 범위 제안이며 법적 적합성 판단이 아니다. 민감 업무를 확장하려면 별도 접근 모델·목적·보존 계약과 전문 검토가 필요하다.
