# 고객지원·고객성공: 응대 기준과 고객별 예외

입력은 승인된 FAQ·정책·내부 에스컬레이션 결정이다. 고객 티켓의 모든 개인 정보를 자동 수집하거나 사수가 고객에게 직접 답장한다고 가정하지 않는다. 외부 고객 음성의 동의·화자 처리는 기존 구성원 동의 절차와 같지 않다.

| 페르소나·상황 | 실제 이용 방식 | 장점 가설 | 단점·실패 조건 | S/M 차이·검증 질문 |
|---|---|---|---|---|
| **CS-L1 신입 상담 담당**. 표준 환불·장애 안내 | 내부 ASK로 현재 기준 확인 → 출처 읽기 → 사람이 고객 응대 | 답변 편차와 교육 중 반복 질문 감소 가능 | 긴 대기·근거 없음 뒤 인계 없음, 고객 이름/결제정보 질문에 포함 가능(G02·G06·G23) | S는 개발자가 직접 응대. M은 교대·스크립트 버전 관리. **응대 제한 시간 안에 확인 또는 상향 요청하는가?** |
| **CS-L2 고객 성공 담당**. 특정 고객 약속/예외 관리 | 과거 결정 확인 → 내부 카드로 서비스 범위 예외 요청 → 사람이 고객에게 전달 | 고객에게 약속한 조건과 내부 결정 이유 추적 | CRM/티켓과 수동 연결, 다른 고객 사례 혼동(G08·G15·G16) | S는 영업/지원 겸임. M은 AE→CS→지원 인계 분리. **동일 고객의 최신 약속만 찾는가?** |
| **CS-L3 시니어·품질 담당**. 응대 기준/예외 검토 | 확정된 FAQ 문서 검토, 반복적인 근거 부족 질문을 비식별·최소 집계로 살핌 | 안내 문서의 빈틈 발견 | 담당자별 질문 수를 숙련도 평가로 쓰면 질문 회피. lead 승격 요구(G04·G20) | S는 교육 담당 겸임. M은 QA 권한이 인사/비공개 사례 접근과 달라야 함. **정답률을 직원 점수로 전환하지 않는가?** |
| **CS-L4 지원 팀장**. 긴급 환불·중대 고객 이슈 | 카드에서 확인할 조건과 책임 범위 판단 → 사유와 결과 확정 → 응대 담당에게 별도 인계 | 여러 교대에 같은 근거를 공유 | 첫 lead 배정·휴가 대행·동일 이슈 중복 카드·알림 폭주(G03·G24·G28) | S는 대표 결정 기다림. M은 교대 책임·상품별 한도. **교대 후 미결과 결정 내용을 이어받는가?** |
| **CS-L5 고객 경험 책임자**. 정책 개선·조직 간 문제 해결 | 공개 가능한 사례 유형/정책 예외의 원인 요약 확인 | 제품/영업 약속과 실제 지원 간 간극 파악 | 전사 민원 원문 조회는 현재 admin 권한 아님. 현재 CSAT/티켓 집계 연동 없음(G07·G20) | S는 대표가 직접 확인. M은 부서 간 개선 요청과 정책 수락 필요. **고객 원문 없이 개선 결정을 내릴 만큼 요약이 충분한가?** |

[J06 정책 Q&A](../journeys.md)는 답변 시간보다 **현재 정책을 올바른 고객 조건에 적용하고, 모를 때 사람에게 연결하는지**를 본다. 외부 응대 자동화는 별도 설계 전 포함하지 않는다.
