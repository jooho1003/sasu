## 4. AI 활용 방식 및 결과 (500자 이내)

> 아래 본문 **[ 494자, 공백 포함 ]** — 제출 폼의 카운트 기준(공백 포함/제외)을 확인하고 필요 시 마지막 문장부터 삭제.

사수는 회의 녹음과 슬랙에서 "지금 결정해야 할 것"을 찾아 담당자에게 카드로 보내고, 내려진 결정을 근거와 함께 기록하는 AI입니다. AI는 세 층으로 나눠 썼습니다. 정리·답변은 Claude Opus 5가 맡되 모든 문장에 회의 발언 구간 인용을 강제해, 인용하지 못하는 답은 내지 않습니다. 결정 감지와 인용 정합성 검증은 규칙 휴리스틱과 Claude Haiku 4.5가 맡아 비용과 일관성을 지켰습니다. 음성은 STT와 화자 등록 기반 식별로 "누가 말했는지"를 붙이되, 정확도 한계를 인정해 교정 UI를 넣었습니다. 개발 전체는 Claude Code로 진행했고, 딥 리서치로 경쟁사(Otter·티로·콜라보)를 검증한 결과 "회의 요약"은 이미 붐빈다는 사실을 확인해 제품을 결정 레이어로 재포지셔닝했습니다. 결과: 폰 원탭 녹음 → 3분 내 화자별 회의록 → 담당자 슬랙에 결정 카드 도착 → 같은 질문에 팀장과 신입이 권한에 따라 다른 답을 받는 흐름이 실제로 동작합니다.

- **개발 과정 AI**: Claude Code (전체 구현, 세션 로그 부록) / Claude 딥 리서치 (경쟁 지형·심사 기준 검증) / AI 페르소나 모의 심사 (기획 스트레스 테스트)

## 6. 서비스 링크

## 7. 스크린샷 5장 (16:9) — 구상

각 장은 "한 문장 캡션이 곧 기능 설명"이 되도록. 실제 화면 캡처 + 상단에 짧은 캡션 띠(썸네일과 같은 심녹색·같은 서체)로 통일감.

| # | 화면 | 프레임 안에 보이는 것 | 캡션 |
|---|---|---|---|
| 1 | **지금 결정 카드 (슬랙)** | 슬랙 DM에 도착한 결정 카드 — "지금 결정" 배지, 마감, 과거 결정 충돌 인용, [재입찰로 결정 / 수락 / 보류] 버튼. 폰 목업 안에 슬랙 화면 | "회의가 끝나면 회의록이 아니라 결정 요청이 먼저 도착합니다" |
| 2 | **권한별로 다른 답 (2분할)** | 같은 질문 "단가 정책 왜 바뀌었죠?"를 좌측 팀장 계정 / 우측 신입 계정으로 — 팀장 답엔 경영회의 인용, 신입 답엔 "권한 내 정보만" 표시 | "같은 질문, 다른 답 — 사수는 알 자격이 있는 사람에게만 말합니다" |
| 3 | **결정 원장** | 결정 목록(상태·담당자·리드타임) + 상세 패널(누가·언제·왜·근거 발언 링크). 한 항목에 "과거 결정과 충돌" 경고 배지 | "회사의 모든 결정이 누가·왜·무슨 근거로 내려졌는지 남습니다" |
| 4 | **화자별 회의록 + 검토 노트** | 좌측 화자 이름 붙은 전사("김 팀장 34:12 …"), 우측 자동 생성 회의록과 검토 노트("3월 재입찰 원칙과 충돌 1건") | "여기까지는 남들도 합니다 — 사수는 여기서 시작합니다" |
| 5 | **폰 원탭 녹음 + 게스트 모드 진입** | 좌측 폰: 캘린더 알림 → 원탭 녹음 중 화면(녹음 표시등·오프더레코드 버튼) / 우측: 게스트 모드 랜딩("온새미로 주식회사에 질문해보세요") | "폰 하나로 시작합니다. 로그인 없이 지금 체험하세요" |

**촬영 원칙**: 실데이터 대신 게스트 모드의 샘플 회사 데이터로 촬영(개인정보·회사 비밀 유의사항 대응) · 5장 모두 같은 브라우저 크기(1920×1080)로 캡처 · 캡션 띠는 1·2번을 가장 강하게(심사위원이 앞 두 장만 볼 확률이 높음).
