# 사수 개발 과정 보완 설명

2026-09-22 후속 개발 원고. 기존 제출 완료본과 구분하며, 새 코드·0053 마이그레이션은 운영에 반영하지 않았다.

## 문제

결정 이유가 슬랙·회의·문서에 흩어져 같은 질문을 반복하고, 담당자가 바뀌면 판단 맥락이 끊긴다. 성공 조건은 질문에서 관련 결정과 이유를 찾고, 근거가 된 원문을 직접 여는 것이다.

## 결과물

질문 → 질문자가 볼 수 있는 원문·결정 검색 → 관련 문단 선택 → 검증된 문단과 출처 번호 → 결정 기록 또는 문서·회의 원문 확인으로 연결했다. 결정은 최신 3건에 한정하지 않고 임베딩 유사도·질문 단어 일치로 찾는다. 원문 화면은 현재 세션·멤버십·RLS를 확인한다.

공개 게스트 데모는 준비된 가상 답변을 보여준다. 최초 검증은 컴포넌트·가상 API와 실제 모델 평가를 분리해 실행했다. 후속 검증에서는 실제 로컬 Supabase와 Next.js·브라우저·Groq·Voyage를 연결해 질문 4건, 오래된 결정과 원문 열람, 권한 회수·삭제 후 차단을 확인했다. 운영 배포 검증은 별도다.

## 본인의 판단: AI·코드·사람

| 맡긴 주체 | 맡긴 일 | 이유 |
|---|---|---|
| AI | 안건 분류, 질문에 관련된 원문 문단 선택, 근거 부족 판단 | 여러 표현에서 관련 내용을 찾는 데 활용한다. |
| 코드 | 권한, 원문 문단 일치, 출처 순서, 원자 저장, 실패 후 거절 | 잘못된 결론을 생성한 모델의 자기 확신에 의존하지 않는다. |
| 사람 | 자료 검토·확정, 최종 업무 결정, 선택된 근거의 적합성 확인 | 원문의 사실성·예외 조건·업무 책임은 자동 검사만으로 확정할 수 없다. |

자유로운 요약·추천을 줄이고 새 답변을 확인 가능한 원문 문단으로 구성하는 선택을 했다. 인용이 있다는 사실만으로 답변의 정확성을 보장할 수 없기 때문이다. 이 결정의 비용과 대안은 ADR-066에 기록했다.

## 실패와 개선

| 실패 사례 | 원인 | 수정 | 재검증 |
|---|---|---|---|
| 오래된 관련 결정이 모델에 전달되지 않음 | 최신 3건만 조회 | 시점 제한 없는 권한·관련도 검색, 미임베딩 단어 검색 | 격리 SQL에서 2020년 결정과 미임베딩 결정 검색, 타 부서·비공개·정정 이전 결정 제외 |
| 문서·회의 인용을 눌러도 원문을 열 수 없음 | 링크를 `#`로 반환 | 세션/RLS를 적용하는 원문 화면과 API | 경로 단위 테스트, 1440/390px 이동·접근 거부·HTML 텍스트 처리 |
| “승인하지 않습니다”를 인용하며 “승인하세요”라고 결론 | 인용의 존재만 확인하고 자유 서술 본문 유지 | 자유 서술 출력 필드 제거, 검증된 완전한 문단으로 본문 조립 | 잘못된 결론이 저장·게시되지 않는 회귀 테스트; 부정어·조건을 자른 문단 거절 |
| 한 출처를 두 번 인용할 때 저장 실패 | DB의 출처 고유 제약과 생성 결과 불일치 | 프롬프트·문단 검증에서 출처 중복 거절 | SQL 실행 중 발견 후 파이프라인·순수 함수·SQL 재검증 |

위 오답은 재현 테스트 사례이며, 실제 사용자에게 전달된 사고라고 주장하지 않는다. 실제 Groq 스모크 평가 7/7 통과는 작은 합성 표본의 결과다. 검색·임베딩·저장은 모의 처리했고 Slack 발송과 원격 DB 쓰기는 0건이다. 상세 명령·결과·한계는 [검증 기록](../verification/grounded-answer-2026-09-22/README.md)을 따른다.

## 배운 방법

다른 문제에서도 먼저 사용자의 성공 행동과 실패 사례를 적는다. 다음으로 AI가 선택할 일, 코드가 강제할 조건, 사람이 확정할 일을 나눈다. 실패를 테스트로 재현하고 수정한 뒤 같은 사례와 새로운 사례를 따로 검증한다. 각 검증이 실제 모델·DB·브라우저 중 어디까지 실행했는지 기록해 다음 작업으로 전달한다.

## 500자 이내 보완 원고

사수는 슬랙·회의·문서에 흩어진 결정 이유를 찾느라 같은 질문을 반복하는 문제를 해결합니다. 질문하면 권한 안에서 관련 결정과 이유를 찾고 원문을 확인합니다. AI에는 안건 분류와 관련 문단 선택을 맡겼습니다. 권한·원문 일치·저장은 코드로 검사하고, 업무 결정은 사람이 확정합니다. 개발 중 최신 결정 3건만 찾아 오래된 이유를 놓치고, 인용은 맞아도 잘못된 결론이 남는 문제를 재현했습니다. 관련도 검색을 추가하고 답변을 검증된 원문 문단으로 구성하도록 고쳤습니다. 단위·SQL·화면 검사와 실제 모델의 합성 사례 7개를 재검증했습니다. 이 과정에서 성공 조건과 실패 사례를 먼저 정하고, AI·코드·사람의 책임을 나눈 뒤 수정 전후를 같은 기준으로 확인하는 방법을 배웠습니다.
