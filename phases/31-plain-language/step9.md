# Step 9: 카드·요약 문체 품질 개선

2026-09-23 사용자의 “다음 개발” 요청에 따라 진행한다. 기준은 기존 PRD §3-7·§10 #21, ADR-065, step6이며 제품 범위·문체 기준은 바꾸지 않는다.

- phase32의 번호 범위 답변 계약은 유지한다. 원문 선택 답변은 문체 분모에서 제외하고 원문/거절 동작은 별도 검사한다.
- 이전 40% 표본에서 남은 사전 금지어와 긴 문장의 원인을 본문 없이 확인한다. 보고서는 고정 사전 규칙·필드·건수만 기록한다.
- 샘플 보고서 경로를 지정할 수 있게 해 기존 9/23 증거를 덮어쓰지 않는다. 같은 카드 3·요약 2건을 포함한 실제 11표본으로 변경 전후를 비교한다.
- `lib/llm.ts`의 문체 지시를 보완한다. 생성 문장만 짧고 쉬운 말로 작성하며 원문 복사 필드·인용 검증·refusal·재시도 계약은 바꾸지 않는다. 문체 위반을 서비스 실패로 처리하거나 후처리로 원문을 치환하지 않는다.
- step6과 실제 코드 대조에서 남아 있던 Slack 진행/실패 안내·작성자/시각 미상·리마인더 문구도 명세대로 정리한다. 문자열과 기존 테스트 기대값만 바꾸며 payload·action_id·저장/발송·canonical refusal 로직은 유지한다. 실제 Slack 발송은 하지 않는다.
- 목표는 카드/요약 5건 중 4건 이상(70% 기준의 최소 정수)을 두 번의 후속 측정에서 만족하는 것이다. 기대값이나 분모를 낮추지 않는다. 미달이면 수치와 남은 문제를 기록한다.
- 새 답변 경로 회귀: 기존 phase32 실제 모델 A01~A10 평가를 별도 경로로 실행한다. 문체 수정으로 근거 선택을 훼손하지 않는지 확인한다.
- 회귀 중 A09가 다시 실패하면 원시 결과를 보존한다. 이번 문체 지시의 대상은 아니므로 원인을 분리한다. 32 step1에서 허용된 프롬프트 보완 2회 중 남은 1회로 일반 기준/예외의 번호 범위 예시를 추가하고 전체 10사례를 2회 확인한다. 기대값은 유지하며 추가 프롬프트 탐색을 반복하지 않는다.
- 검증: 관련 단위 → 실제 모델 변경 전후 → lint → build → 전체 unit. UI/SQL 경로는 바꾸지 않는다.
- 기록: `docs/verification/llm-style-followup-2026-09-23/`. 코드 관계는 실제 호출처를 확인한다. Graft/Archify 도구가 없으면 누락을 명시한다.
- 사람 읽기·쇼케이스 판단·운영 적용은 별도 조건으로 유지한다. 자동 전체 커밋 실행기는 쓰지 않는다.
