# Step 2: 녹음부터 검토·확정까지

상태: 미실행. step1 통과 후 수행. 원천은 상세 설계 §2·§4~§6·V01~V10.

## 작업

- `/d/[dept]/reviews/record`와 `회의 녹음` 진입, 녹음 방식·참석자 동의·테스트·입력별 미터·일시정지·종료를 구현한다.
- 초기 공개 범위는 새 녹음만 부서장 전용. 녹음 중 부서/입력 변경을 잠그고 녹음 종료·로컬 저장·서버 저장 완료 상태를 구분한다.
- 복구 후 현재 권한 재검증, 재생/내려받기, 원본 구간 업로드/서버 검증, 기존 ReviewDetail 연결을 구현한다.
- 구간 원본 순차 재생·seek·WAV 결합 내려받기·재추출을 지원하고 기존 단일 파일의 저장 편집본/버전 충돌 처리를 보존한다.
- 실제 Groq 전사 → 수정·확정 → 기존 인용 요약/분류 경로까지 합성 음성으로 완주한다. 원장 직접 자동 생성 금지.
- 모바일/키보드·화면 이탈·네트워크 단절·오류 회복을 테스트한다. 실제 브라우저 지원 결과에 맞춰 모드를 공개한다.
- 로컬 체크포인트를 step1의 키로 AES-GCM 암호화하고(키는 메모리만) 복구 시 키 재발급 → 복호화 순서를 지킨다. 프로필 파일에서 평문 PCM 패턴이 0건임을 확인한다(V15).
- 수집 강화(§12): wake lock, `devicechange`·트랙 `ended`/`mute` 처리, 공유 선택 힌트, 회의 출처·건강 카운트·`continues_review_id` 메타데이터, `.m4a`/`.mp4(audio)` 파일 허용. 입력별 음량 프로파일과 클리핑 비율을 `capture_metadata`에 남긴다(§11.1).
