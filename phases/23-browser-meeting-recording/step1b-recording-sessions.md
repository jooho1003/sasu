# Step 1-B: 녹음 시작 전 서버 세션

2026-09-25 사용자가 **별도 녹음 세션을 만들고 전송 시 자료로 전환**하는 방식을 선택했다. 원천은 PRD §3-4·§8, ADR-070 결정 1·2·8이다. 이번 독립 단계는 음성 업로드 전 세션 수명 주기를 구현한다. 자료 전환·구간 업로드/검증은 다음 서버 단계에서 연결하고, 실제 입력 영속 녹음·제품 화면·운영 배포 게이트는 유지한다.

## 구현

- `review_recordings`: 녹음자·부서·동의 스냅샷·입력 방식·제목·공개 범위·회의 출처·키 버전·24시간 만료. 세션 ID를 이후 자료 ID/HKDF/AAD에 그대로 쓴다.
- 시작 RPC: 세션 멤버십과 `review_editor`/`can_see`, 조직 스위치, 참여자 동의, 녹음자 자동 포함, 사용자 3건·부서 10건, 동일 입력 멱등성. 다른 ID·권한 필드는 본문에서 받지 않는다.
- 목록/단건은 세션 클라이언트+RLS로 본인만 읽고, 쓰기는 RPC만 허용한다. 조직 관리자는 진행 건수만 읽는다.
- 키 RPC는 자료 행 대신 살아 있는 세션을 검사한다. 키 버전별 비밀 선택은 서버 환경에서만 하고 이전 버전 비밀은 최대 세션 수명 동안 유지한다. 알 수 없는 버전은 거부한다.
- 폐기·만료·참여자 철회/탈퇴는 되살릴 수 없는 끝 상태다. 스위치 off에서도 목록·폐기는 허용하고 시작·키는 거부한다. 서버 세션 생성만으로 음성/자료/LLM job은 생기지 않는다.

## 검증

계약/키 버전 단위 테스트를 먼저 작성한다. 요청 본문 권한 위조·알 수 없는 키 버전·no-store·오류 응답을 라우트 테스트로 확인한다. 실제 PostgreSQL 문법/RLS/RPC는 기존 격리 PGlite 하니스로 실행한다. 이는 실제 Supabase Storage 업로드 또는 동시 트랜잭션 부하 검증과 다르다. lint·build·전체 단위 검사를 실행하고 Graft/Archify 결과와 미실행 범위를 `docs/verification/recording-sessions-2026-09-25/`에 기록한다.
